Week 08 / Lesson 10

Expose ingest, search and ask

Connect the pieces through a testable HTTP boundary.

The service layer should be understandable before adding HTTP. The route's job is to validate a request, call those pieces and map failures to a response. Dependency injection here means passing store/embed/llm into create_app; it lets a test replace slow or costly boundaries with deterministic functions.

A small route trace

For POST /search with {"question":"return deadline"}, a Pydantic body validates the question, the injected encoder returns a vector, Store searches within trusted tenant red, and the route returns hits. For /ask, the same retrieval feeds answer_question. For /ingest, a validated source becomes chunks, each is embedded, and the store upserts them. Review the existing route lesson only if decorator/body syntax blocks this step.

# Miniature shape example; not the project implementation
@app.post("/echo")
def echo(body: EchoBody):
    return {"text": body.text}

The decorator registers a function for an HTTP method/path; body is the validated input model instance. Returning a dictionary lets FastAPI serialize JSON. Use synchronous routes for this synchronous tiny lab; placing blocking work inside an async route without care would block its event loop. Production concurrency is outside this week's implementation.

Implement and test the seam

Edit create_app in rag.py against contract.md. Reject extra fields, wrong types and whitespace-only questions. The trusted fixture tenant comes from create_app's argument; the request may not choose it. Map invalid generated output to a generic 502, provider timeout to 504. Do not turn unexpected bugs into a misleading success.

Operate the local fixture

Read run_local.py. It supplies three keyword-count coordinates and a generator that always abstains. Those completed adapters let you observe HTTP/storage wiring; they are deliberately not a finished semantic RAG solution. runtime/project-db is generated persistent output, ignored by Git. The finally block closes the store after server shutdown.

# Terminal A, weekly root; starts only after rag.py is implemented
.venv/bin/python projects/manual-rag/run_local.py
# Terminal B, weekly root
curl -sS http://127.0.0.1:8008/ingest -H 'Content-Type: application/json' -d '{"doc_id":"demo","title":"Returns","text":"A receipt is required.","version":1}'
curl -sS http://127.0.0.1:8008/search -H 'Content-Type: application/json' -d '{"question":"receipt"}'
curl -sS http://127.0.0.1:8008/ask -H 'Content-Type: application/json' -d '{"question":"receipt"}'

Expect {"chunks":1}, a hit with trusted tenant red and ID red:demo:v1:0, then {"answer":"Insufficient evidence.","citations":[]}. That last response proves mock wiring only. Stop Terminal A with Ctrl-C before opening the same embedded store elsewhere. A port conflict means another listener owns 8008; diagnose it before changing application code.

Predict a failure

A provider raises TimeoutError("SECRET"). What should the client and log see?

Hint

Separate public error class from sensitive exception contents.

Explained answer

The client sees generic 504 detail. A safe event can contain request ID, provider label, elapsed time and error class, but not the exception's raw message or request payload. Test the response for absence of SECRET.

Independent variation: inject an encoder that fails once during ingestion. Explain what data exists after failure and how stable IDs support recovery. Document the result in debugging-note.md, completing its reproduction/fix/regression fields.

Primary reading: fastapi official documentation. Check the mechanism, then return to your own example.
