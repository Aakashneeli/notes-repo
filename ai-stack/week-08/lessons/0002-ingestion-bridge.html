Week 08 / Lesson 02

Follow one document into the system

Identify the extraction-to-chunking seam without replacing unfinished earlier work.

Retrieval augmented generation (RAG) gives a model selected external text while answering. It has two different lifecycles: ingestion prepares searchable evidence; a query selects evidence for one question. Uploading a file is not the same as making it searchable.

A concrete trace

Imagine an uploaded returns policy. Earlier ingestion should validate the upload, extract plain text and assign an owner and document identity. Week 8 begins with that extracted text. It creates chunks, turns each chunk into a vector, and stores vectors beside provenance. Later, “When can I return a book?” becomes a query vector; retrieval chooses chunks; the model sees the chosen text and returns an answer with IDs. The application checks those IDs before returning them.

A document record identifies the whole source. A chunk record identifies an exact excerpt. An embedding is a numerical representation of the excerpt produced by a particular model. Storing only vectors loses the evidence needed for prompts and citations. Storing only text loses the vector search mechanism.

Trace before designing

Guided question: ingestion succeeds for text storage but embedding fails. Is the document searchable? Where should status change?

Hint

Ask which step creates the search representation.

Explained answer

Raw text exists but no valid vectors exist yet. Mark indexing failed or pending, retain source identity, and retry with stable IDs. Mark searchable only after the required writes complete. An existing background job's “extracted” state need not mean “indexed.”

Independent variation: explain what happens if the same document is indexed twice, then if its text changes without changing its version. Record both in decisions.md. Next, learn the boundary where the eventual answer is generated.
