Week 08 / Lesson 11

Locate the first failed stage

Build a golden set and distinguish retrieval, context and generation failures.

A golden question pairs a realistic question with expected evidence and an answer criterion. It lets you diagnose the pipeline rather than judge how fluent a reply sounds. An unanswered question can be correct when the corpus lacks evidence.

Create the assessed set

Read golden-seeds.json: 20 teaching cases including paraphrases, unknowns, a tenant trap and an injection request. They are starting examples, not your completed deliverable. Read each expected source in documents.json. Create projects/manual-rag/data/golden.json with 15–25 cases, independently rewriting or adding at least five. Keep seeds unchanged. Keep some new paraphrases aside to check whether a fix merely memorizes the original wording.

Read templates/evaluation-row.md; copy its fields into learner-owned evaluation-report.md for each case. A report needs configuration, per-question results, failure classification and a controlled comparison. “Tests passed” is not an evaluation report.

One worked failure

For q1, the expected document is returns and the answer is 30 days from delivery. Run /search without generation. If only shipping appears, label retrieval miss. If returns was retrieved but omitted by your budget, label context-selection loss. If returns enters the prompt but the model says 90 days, label unsupported generation. If the answer says 30 days but cites shipping, label citation failure. Multiple labels can be warranted; fix the earliest causal failure first.

For debugging, try an oracle-context run: manually provide the correct passage to answer_question with the same model/configuration. If it now answers correctly, investigate retrieval/selection. If it still fails, investigate prompt, schema repair or generation. This is a diagnostic intervention, not a score to mix into the baseline.

Compute a metric you can explain

For this lab, hit@k is the fraction of answerable questions whose top-k retrieved documents include at least one expected document. It is deliberately simpler than evidence recall: a question needing two sources can get a hit while missing one. Report all-required-source coverage as a separate count when appropriate. Keep unknown questions outside the answerable denominator.

Guided scoring

Expected sources are [returns, support]; retrieved sources are [returns, shipping]. Is hit@2 a success? Is evidence complete?

Hint

Compare “at least one” with “all required.”

Explained answer

Hit@2 is 1 for that row, but only one of two required sources is present. A sentence about support hours cannot be grounded in returns alone. Retain both measurements instead of picking the more flattering one.

Independent variation: write an unknown question that shares words with a source. Does a high similarity score justify answering? Explain why you need an abstention judgement. Track hallucination notes as specific unsupported claims, not just a vague “bad answer.”

Make one controlled improvement

Hold corpus, model, questions and generation settings fixed; change only chunk overlap, k or prompt policy. Rerun the same cases and held-out variations. Report regressions, latency and unanswered cases. Do not select a universal similarity threshold from one question. Keep synthetic-vector, real-embedding and live-generation results in separate sections.
