Week 08 / Lesson 07

Persist and filter a local vector store

Verify retrieval scope and persistence using known vectors.

A vector store connects point identity, a numerical vector and payload. Payload is metadata/text carried beside the vector; a collection specifies compatible vector settings. We use Qdrant's embedded local mode for a small single-process lab. No server, cloud account or GPU is needed. A later server deployment has different concurrency and operational properties.

Read, run, trace

# Start: ai-stack/week-08
.venv/bin/python -m practice.examples store

Expect ['red:1']. In client_demo, a temporary directory holds the real local database. The example creates a 3-dimensional cosine collection, inserts two points, closes, reopens and queries. Both points have the same vector; only the red tenant should be returned. The temporary directory is cleaned after the client closes. This demonstrates local persistence, not a running Qdrant server.

PointStruct describes ID/vector/payload. upsert inserts or updates the same point ID. query_points(...).points returns scored matches. with_payload=True requests source fields needed by later prompts. The project uses UUIDs derived from stable chunk IDs because arbitrary citation strings are not Qdrant point IDs.

Filter before choosing top-k

Payload filtering expresses exact conditions that vector similarity cannot guarantee. In our fixture red's best point has score lower than blue's. Searching globally for one result then removing blue can leave no answer even when red has useful evidence. Put the trusted tenant condition inside the database query. Filtering afterwards also risks disclosing private context before removal.

As a tiny bridge, implement allowed_hits in practice/exercises.py and check it:

.venv/bin/python -m pytest practice/test_exercises.py -k filter -q
Hint

Use a comprehension with an exact metadata comparison; rows with no tenant do not match.

Explained beginner answer
return [hit for hit in hits if hit.get("tenant") == tenant]

This teaches the boolean condition only. Do not use post-filtering as your project's retrieval implementation; place the condition in Qdrant's query.

Implement the storage lab

From the weekly root edit only Store in projects/manual-rag/rag.py. Follow contract.md for dimensions, finite nonzero vectors, equal batch counts and UUID mapping. Validate the entire batch before writing any point: otherwise one bad vector can leave a partially accepted batch. Content deduplication must preserve provenance and tenant ownership.

.venv/bin/python -m pytest projects/manual-rag/tests -k 'store or collection' -q

Each test uses its own temporary path; it does not touch your runtime database. A persistent-path lock error often means a previous client is still open. Close the client in finally, which runs even after an error; do not delete an unrelated database to clear a lock. Reopening with the wrong dimension should fail clearly, without retaining the lock.

Independent variation: add two different tenants with identical source text, then upsert one updated chunk. Predict the count and ownership before querying.
