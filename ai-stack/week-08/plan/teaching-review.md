# Teaching sufficiency review
Reviewed separately from coverage and executable checks.
- Orientation begins with disclosed exposure and three probes; earlier lesson links are targeted.
- Each new mechanism has a concrete trace before a guided check and independent variation.
- Messages: envelope traversal → decoded fragment assembly → mid-word variation.
- Validation: three gates → rejected outputs → bounded repair → factual-support counterexample.
- Chunking: index trace → overlap drill → metadata implementation → sentence/window comparison.
- Vectors: numerical trace → zero/dimension failures → model compatibility and real encoder seam.
- Store: complete tiny persistence/filter example → metadata drill → learner Store implementation.
- Context: question/source trace → ID failure → answer contract → stale-version variation.
- API: route shape and injection trace → fixtures/tests → local smoke → encoder failure variation.
- Evaluation: one failure across stages → computed hit@k → multisource counterexample → controlled rerun.
- Store choice: comparison criteria → worked scenario → independent changed deployment constraint.
Main implementation remains learner-owned. Beginner answers appear only for isolated drills.
No lesson/page length used as evidence of quality. Model/provider runtime remains a distinct evidence gate.
