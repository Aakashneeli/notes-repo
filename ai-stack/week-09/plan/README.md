# Flexible sequence

Start at Lesson 1. Each numbered lesson is one outcome, with a natural pause after its variation.
1. Baseline and environment; use only the bridge refreshers indicated by your failed probe.
2–3. State patches, nodes and branches; practice before graph construction.
4–5. Bounded tool and terminal failure paths; implement graph in small tested increments.
6. API integration; keep fixture and real-backend evidence distinct.
7–8. Trace reading, then live inspection of at least ten runs if prerequisites are available.
9–10. Model selection/tokenization, then one real CPU experiment (or record the concrete blocker).
11. Serving tradeoffs and vLLM concept note.
12. Read code, debug, explain and vary independently.

At the next session, retrieve yesterday's state transition without looking. About two days after implementation, repeat one failed/slow/tool case with a new input. About a week later, redraw the graph and change the routing rule from memory. Adjust dates to your pace; missed dates don't reset progress. Interleave tool validation and trace interpretation after each has been learned separately.

Learner updates progress.md only with evidence and assistance disclosed. assessment.md is the final ability gate; coverage.md maps source scope; file-map.html shows where each file is taught. teaching-review.md records tutor judgments, not learner learning.
