Week 09 / Lesson 08

Inspect ten real LangSmith runs

Collect trace evidence while keeping offline checks and live service work distinct.

This lab fulfills the roadmap's live tracing requirement. It is a learner action: it needs access to a LangSmith workspace, an API key and an appropriate project/region. Review current account limits and data handling before enabling it. We have not created or changed an external account. If you cannot use LangSmith yet, complete offline preparation and record the blocker; the live requirement remains incomplete.

Prepare locally first

Read trace_runs.py, a supplied runner around your completed graph. It imports LangSmith after choosing offline/live mode, runs twelve fictional inputs, times each request and writes a fresh JSONL file. JSONL means one JSON object per line. open('x') refuses to overwrite evidence. --out chooses your generated destination; use a new name for later attempts.

At the weekly root, run:

.venv/bin/python projects/agent-rag/trace_runs.py --out runtime/traces/offline-01.jsonl

Expect twelve rows, mode offline, with status/reason and elapsed time. The run IDs may be absent; no upload is attempted. If graph construction raises NotImplementedError, finish Lessons 3–6. If a timeout escapes, inspect the node that should convert it. This runner is not a substitute for your tests.

Live setup, explicitly chosen by you

In your own LangSmith UI select the correct workspace and region; create or choose a private tracing project named week09-learning. Obtain a scoped API key using your account's supported key controls. If the account uses a regional/custom endpoint or requires a workspace ID, use its documented values. Do not assume a default endpoint is correct for every account.

From the weekly root in Bash, set session-only values. read -s hides input, and the variable's value is not typed into command history. Never paste keys into notes.

read -rsp 'LangSmith API key: ' LANGSMITH_API_KEY
export LANGSMITH_API_KEY
export LANGSMITH_PROJECT=week09-learning
# Set LANGSMITH_ENDPOINT / LANGSMITH_WORKSPACE_ID only if your workspace requires them.
.venv/bin/python projects/agent-rag/trace_runs.py --live --out runtime/traces/live-01.jsonl
unset LANGSMITH_API_KEY
export LANGSMITH_TRACING=false

The explicit live flag enables tracing for this process. All prompts and documents are fictional. Use LangSmith's documented hide-input/output or processing hooks before adapting this to private data; metadata and error strings require review too. The runner waits for graph tracing callbacks and flushes its explicit LangSmith client with a 15-second bound; this reduces early-exit loss. SDK success alone does not prove delivery: check the UI. Missing traces? Check project, endpoint, credentials, sampling and upload errors, then run one fresh case. Do not print your key to diagnose it.

Inspect rather than count invocations

Open the project, find each root run by case/time or saved ID, expand its graph and child nodes, inspect inputs/outputs and timing. Record at least ten distinct runs in trace-notes.md, using templates/trace-row.md for fields. Use private run IDs/URLs; no public sharing is needed.

  • Success: refund or hours; verify answer and authorized citation.
  • Failure: retriever-fails or model-fails refund; find the errored child and the fallback root output. State whether root itself failed or handled a failure.
  • Slow: slow refund; locate the deliberately delayed search child.
  • Tool error: lookup:broken; inspect tool TimeoutError and fallback reason.
  • Other cases: weak evidence, invalid citation, missing lookup and hostile document content.

Do not manufacture a red root status if the application correctly caught the error. The error span is still inspectable. In the notes, distinguish expected synthetic failure injection from an unexpected application defect.

Compare prompts and models carefully

The fixture has no prompt-sensitive model behavior, so tagging it “prompt-v2” proves metadata plumbing only. For an actual comparison, use the same three evaluation questions and corpus with your real Week 8 generation adapter. Version two prompt texts (for example, add an explicit abstention rule), hold model and generation settings fixed, and record support/citation judgments alongside latency. Then hold the winning prompt fixed and compare two available models. If credentials or downloads are unavailable, write the exact comparison plan and label results unperformed.

Worked judgment: A answers “30 days” with the refund citation in 800ms; B answers “7 days” with the same citation in 500ms. B is faster but unsupported. A trace shows the outputs; your evidence comparison reveals the quality regression. Variation: add an unanswerable question and predict which rule should trigger. Record live status honestly in plan/progress.md and continue to local model selection.
