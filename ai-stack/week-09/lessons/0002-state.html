Week 09 / Lesson 02

State is a shared snapshot

Predict how a small node changes state without replacing unrelated fields.

A workflow needs a place to carry the question and intermediate results. We call that snapshot state. A node reads it and returns a patch: just the keys it changes. This lets you inspect the boundary between operations.

A small execution trace

state = {"text": "Database OUTAGE", "queue": "unassigned"}
patch = {"urgent": "outage" in state["text"].lower()}
next_state = {**state, **patch}
print(next_state)

state["text"] looks up a dictionary key. .lower() creates lowercase text; in tests for a substring; the result is a Boolean. ** inside a dictionary copies key/value pairs. Later pairs replace matching keys. Expect text unchanged, queue “unassigned” and urgent True. Neither the original state nor the patch contains an on-call decision yet.

In examples.py, class Ticket(TypedDict, total=False) documents expected keys. total=False means keys may be absent in partial snapshots; it does not insert defaults. A type annotation helps tools and readers, but does not reject a runtime integer. That is why the API and tool need runtime validation.

LangGraph applies node patches to its state channels. Our fields use the default replacement behavior. If a node returns {'queue':'helpdesk'}, it replaces queue, leaving text and urgent untouched. Do not return an unrelated string where the graph expects a dictionary update.

Common failure: “the key exists in the type”

classify({}) raises KeyError: 'text': the type did not create a value. Debug by identifying the first reader and the earlier writer. In the RAG workflow, hits must be written before answer generation; an empty list is a valid value, while a missing key may signal an invalid route. Using .get(..., []) everywhere can hide that route bug.
