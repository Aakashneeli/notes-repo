Week 09 / Lesson 06

Put the graph behind the service boundary

Connect validated HTTP input to the graph and identify what a fixture cannot prove.

Your API should expose a small response, not dump the whole graph state. Request validation belongs before the first node; output selection belongs after the graph ends. A graph invocation takes Python data, whereas an HTTP client sends JSON bytes which FastAPI parses.

A small unrelated endpoint explains the wrapper

from fastapi import FastAPI
from pydantic import BaseModel, ConfigDict, Field
class TicketRequest(BaseModel):
    model_config = ConfigDict(strict=True, extra='forbid')
    text: str = Field(min_length=1, max_length=500)
app = FastAPI()
@app.post('/ticket')
def ticket(body: TicketRequest):
    return {'accepted': body.text}

The decorator associates POST /ticket with a function. The annotated body tells FastAPI to validate JSON as TicketRequest. A number or extra team field produces 422. min_length=1 alone accepts a space; your project must strip and then reject blank text. A Pydantic field validator can do that after type validation. Prefer a normal def handler for our blocking fixture calls; putting synchronous model work inside async def does not make it nonblocking.

Integrate your real Week 8 work when it is ready

The fixture is a prerequisite bridge, not a completed RAG service. Read the real signatures in Week 8 rag.py. When you have implemented them, add your own projects/agent-rag/real_adapter.py. It must implement this week's search/generate/lookup interface while reusing your store, encoder and answer function. Do not copy all Week 8 code here.

Adapter data flow: embed(question) → store.search(vector, tenant) → translate each chunk_id to this contract's id → graph selects hits → adapter restores the Week 8 expected chunk fields → answer_question(question,hits,llm). Keep original provenance. Implement document lookup using stored authorized records, not a generated guess. A chunks-to-document mismatch needs an explicit ID choice in decisions.md.

One interface mismatch needs explicit handling: Week 8 answer_question raises ValueError("invalid model output") after its bounded repair attempt, whereas this graph validates a returned draft. In your adapter, translate that documented output-validation failure into an invalid draft so the graph produces invalid_answer, or define a narrow domain exception and teach the answer node to handle it. Do not swallow unrelated ValueError exceptions. The graph calls generate once; the reused Week 8 helper may make its own bounded two provider calls. Record both limits. A provider-selected abstention also needs an explicit policy rather than being mislabeled as a factual answer.
