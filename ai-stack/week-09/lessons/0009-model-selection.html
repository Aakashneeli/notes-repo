Read the model before downloading it

Choose a compatible small model and explain its tokenizer and license evidence.

The Hugging Face Hub stores model repositories: weights, configuration, tokenizer files and a model card. A repository is not automatically a hosted endpoint or a guarantee of quality. The card tells you intended use, limitations and license metadata; verify the actual license and chosen files before reuse.

A concrete candidate

For a small CPU experiment, this course uses HuggingFaceTB/SmolLM2-135M-Instruct. Its card lists Apache-2.0 and an instruction-tuned 135M-parameter model. A parameter is a stored learned numeric value. The small size helps keep the experiment bounded; it does not establish that the model is reliable at JSON, retrieval reasoning or tool use.

Open its Files/history view, choose a full revision commit SHA, and record the ID, license, intended language/tasks, limitations and revision in local-inference.md. This is your experiment record, not prefilled evidence. Pinning a revision prevents a moving repository branch from quietly changing your experiment. Review artifact sizes and available disk before downloading.

Tokens are model-specific pieces

A tokenizer transforms text into integer IDs consumed by a model. It can split words, punctuation and spaces into pieces; do not assume one word equals one token. The matching tokenizer also supplies special chat markers. A chat template arranges roles and separators into the format expected during training. Swapping tokenizers just because dimensions look plausible changes the meaning of input IDs.

Worked conceptual trace: your message list contains role=user and content=“Refund days?”. The chat template surrounds it with model-specific role markers; the tokenizer maps the resulting string to IDs; the model predicts continuation IDs; decoding converts those back to text. The actual IDs must be observed with the chosen tokenizer, not invented from this illustration.

A pipeline is packaging, not magic

A Transformers pipeline combines preprocessing, model execution and postprocessing. In our later runner, text-generation is the task, device=-1 selects CPU for the pipeline, and max_new_tokens=32 bounds generated continuation length. The model's input context limit and the output allowance are different constraints. do_sample=False selects deterministic decoding behavior for comparison; exact reproducibility can still depend on software/hardware.
