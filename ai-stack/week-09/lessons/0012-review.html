Week 09 / Lesson 12

Prove ownership and return later

Read one framework path, repair a bug and explain the whole workflow independently.

You have prepared the mechanisms separately. This lesson checks whether you can put them together without copying. First close answers and redraw your graph. For each node, name input keys, output keys, external capability and failure route. Compare the drawing against your code only after finishing.

Read a real dependency with a question

Start at the weekly root. Open codebase-reading/reading-log.md and choose one question: “Where does compile turn my builder into a runnable graph?” Inspect the installed implementation path:

.venv/bin/python - <<'PYCODE'
import inspect
from importlib.metadata import version
from langgraph.graph import StateGraph
print('langgraph', version('langgraph'))
print(inspect.getfile(StateGraph))
print(inspect.signature(StateGraph.compile))
PYCODE

Read the returned source file at compile and its immediate calls; leave installed code unchanged. Then compare one related example/test in the official source or documentation, recording the exact version/path. The goal is one call path, not every dependency. Trace caller → builder state → compiled result and write a one-page explanation with one pattern you can safely apply. The lockfile shows LangGraph's ecosystem dependencies; this is LangChain awareness without importing a high-level agent factory you cannot explain.

Deliberate debugging

Use a separate local branch or a small temporary edit to break your own threshold check or tool validation. Predict which test will fail, run it, then restore only that edit and rerun the regression. Do not use a repository-wide reset. Record the actual before/after case in projects/agent-rag/debugging-note.md and a shorter memory cue in weekly-logs/mistakes.md.

Run all learner checks from the weekly root:

.venv/bin/python -m pytest practice/test_exercises.py projects/agent-rag/tests -q

Unfinished functions fail normally. Tests passing means these contracts passed; it does not prove live integration, answer support or independent understanding. Use reference/debugging.html to isolate environment versus graph failures.

Four explain-backs, then a variation

  1. What is stored in LangGraph state at each step? Trace strong retrieval, weak retrieval and lookup timeout.
  2. Why is this called an agent workflow? Correctly distinguish your predefined workflow from a model-directed autonomous agent.
  3. How do LangSmith traces differ from backend logs? Use a real inspected run and explain why parent/child timing cannot simply be summed.
  4. When choose hosted APIs, Ollama/llama.cpp or vLLM? Use local measurement and deployment constraints.

Write or record answers and link them from the weekly log. Next add a new query classification rule, test one input that changes route and one that must not. Explain the safety impact before editing. Ask the tutor to challenge a particular claim rather than produce the solution.

Author verification and learner evidence

Read VALIDATION.md for what course preparation verified. maintenance/verify.py checks local navigation and syntax, not mastery. test_examples.py verifies the ticket example; test_infrastructure.py checks fixture behavior. The tutor maintains these; run them when troubleshooting supplied infrastructure, not to fill progress boxes.

.venv/bin/python maintenance/verify.py
.venv/bin/python -m pytest maintenance -q

Review plan/coverage.md against evidence, then update plan/progress.md and use plan/assessment.md's independent gate. A live service or hardware blocker stays visible. Author-created files never count as learned.

About two days later, use templates/review.md to append a fresh recall attempt: trace a new tool failure without looking. About one week later, redraw the state model and implement a small route variation from memory. If you need hints, record them and choose a smaller next exercise.

Session activity belongs in logs; durable understanding belongs in a justified record.
