Week 09 / Lesson 03

Nodes choose work; edges choose the next step

Trace and construct a conditional graph without confusing building with running.

Open practice/examples.py at ticket_graph. A node is a named operation; an edge connects operations. START and END are special entry/exit markers. The builder records structure. compile() produces an executable graph; invoke(input) actually runs it.

add_node('classify', classify) passes the function itself, not classify(...)'s result. The two lambda state: expressions are small unnamed functions returning queue patches. An ordinary named function could do the same job.

Predict the branch

For “Database outage”: START → classify writes urgent=True → choose reads urgent and returns “fast” → the edge map selects fast → fast writes queue=on-call → END. For “billing”: urgent=False selects normal and writes helpdesk. A conditional-edge function returns a destination label; it does not return a state patch.

From the weekly root, inspect exactly those updates:

.venv/bin/python - <<'PYCODE'
from practice.examples import ticket_graph
for update in ticket_graph().stream({'text':'billing'}, stream_mode='updates'):
    print(update)
PYCODE

Expect {'classify': {'urgent': False}}, then {'normal': {'queue': 'helpdesk'}}. Updates are not full snapshots. If you expect text in each row, you are confusing a patch with accumulated state.

One failure worth predicting

If you add both an unconditional edge from classify to normal and a conditional edge from classify, you can schedule unwanted work. Use one clear routing strategy at that boundary. If choose returns “urgent” but the map only knows “fast” and “normal”, your labels disagree. Inspect the branch return and mapping before rewriting the whole graph.

Edit next_queue in exercises.py, starting at this weekly root, then run:

.venv/bin/python -m pytest practice/test_exercises.py -k next_queue -q
Hint — open after trying

A conditional expression can return one of two strings. It must read urgent, not queue.

Explained answer — compare with your attempt

return "fast" if state["urgent"] else "normal". Both branches terminate; there is no loop or model decision in this example.

A predefined route is accurately called a workflow. Agents can choose actions dynamically with a model, but drawing branches does not establish that. The source uses “agent workflow”; in your explain-back, distinguish orchestration from autonomy instead of claiming all LangGraph programs are autonomous.
