# Flexible study sequence

No fixed session count. Stop when attention drops; finish the current small check and
record the next action. Existing earlier work is not evidence of prerequisite mastery.

1. Lessons 1–2: predict dictionary/validation behavior; run bridge and environment checks.
2. Lessons 3–4: inspect HTTP and distinguish input locations; state resource contract.
3. Lesson 5: practice omission/False/null, then implement project schemas.
4. Lessons 6–7: design state transitions, CRUD and filter-before-page behavior.
5. Lessons 8–10: errors, auth, router wiring and lifecycle; obtain first passing API slice.
6. Lesson 11: finish full endpoint/negative checks and write a real regression.
7. Lesson 12: run curl/Swagger/Postman; add checks, export and re-import your collection.
8. Lessons 13–14: code reading, lifecycle note/diagram, README, local Git review and explain-back.
9. After 1–2 days: no-code recall and reconstruct one negative test. Around 7 days: independently vary a contract and document affected layers.

You can revisit a lesson; do not restart the course or overwrite earlier evidence.
Check [progress](progress.md) only with the [assessment](assessment.md) evidence.
Use [file guide](file-map.html) for navigation and [coverage](coverage.md) for scope.

## Supported mechanism checks

During lesson 5 use practice/test_mechanisms.py -k dial (6 cases); in lesson 6 use
-k counter (3 cases); in lesson 9 use -k dependency (1 case). Each first-use lesson
provides the complete command and explains the corresponding completed code. These
are instructor examples, not additional assessed project requirements or learner evidence.
