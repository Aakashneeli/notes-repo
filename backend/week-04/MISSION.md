# Mission: Independently own a Python HTTP API

## Why
Build toward independently creating, debugging and explaining Python-first AI backends. This week, make a local service whose requests, validation, state changes, authentication and failure behavior you can reason about without copying a finished implementation.

## Success looks like
- Implement an in-memory Task CRUD API with router/schema/service separation.
- Test every endpoint and negative case, reproduce a real bug and explain its fix.
- Use curl, OpenAPI and Postman, then export and reproduce manual checks.
- Explain a request lifecycle and independently vary a requirement after a delay.

## Constraints
- Exposure to Python and basic Git; no independent mastery assumed from earlier desks.
- Flexible pace, small bridges, progressive hints, immediate local feedback.
- Preserve learner work; no publishing, paid services, account changes or outside messages.
- Main implementation and assessed design decisions remain learner-owned.

## Out of scope
- DSA, NeetCode, algorithm interview work, complexity drills and their logs.
- Database implementation, ingestion/jobs, cloud, deployment and advanced auth.
