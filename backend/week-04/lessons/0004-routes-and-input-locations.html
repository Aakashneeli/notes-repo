Trace routing and typed parameters

Two passes: first understand and predict; then run the guided check. Pause between sections when needed. Worked mechanism and debugging practice.

Explain where FastAPI gets each argument.

A decorator such as @app.get("/greetings/{number}") registers a function for a method/path pair when the module imports; it does not call the function immediately. On a matching request FastAPI prepares arguments and invokes it. number comes from the path because its name appears in braces. loud comes from the query. A Pydantic model parameter represents the body. Header and Depends declarations request other input sources.

In /greetings/2?loud=true, both values initially arrive as text. number: Annotated[int, Path(ge=1)] asks for an integer at least 1. loud: Annotated[bool, Query()] = False has a default when omitted and parses accepted boolean text. Annotated pairs the ordinary Python type with framework metadata; it is not a runtime call to your handler. The handler receives 2 and True, chooses the uppercase branch and returns a dictionary. FastAPI serializes it to JSON.

Read a signature as a request contract

Consider the existing greeting handler one piece at a time. def greeting(...) is still an ordinary Python function. number is its local argument name. int says what kind of value the function expects. Path(ge=1) tells FastAPI how to obtain and constrain it. = False gives loud its default. The return annotation describes the returned Python data; the decorator's response model declares the public output schema.

If you directly call a Python function, FastAPI is not sitting between you and its parameters. HTTP requests enter through the framework and receive framework validation; an ordinary function call does not automatically execute route parsing or dependency injection. This matters when choosing whether a test should call a pure helper directly or send a request through TestClient.

Now imagine GET /greetings/2 returns 404. Work backward: is Uvicorn serving the module you edited? Is the method GET? Does the registered path include a prefix? Is the router included? A validation problem in number would normally give 422 after a matching route, so repeatedly changing the number's type annotation is unlikely to fix a completely unregistered router.

Design before decorators

Open projects/task-api/README.md and read the contract. A collection is /tasks; one task is /tasks/{task_id}. Avoid action names such as /getTask because the HTTP method already expresses the operation. Route ordering matters: a fixed path such as /tasks/stats must not be accidentally swallowed by a dynamic path. We do not require that extra endpoint this week.

Read routes.py now: APIRouter groups task routes under one prefix. It is not yet attached to an app. Read main.py: create_app() is a factory returning a fresh app and currently only /health. __init__.py marks the importable package and intentionally does nothing. These are supplied shells; you will add wiring in lesson 10. A decorated router with no include_router call produces 404.
