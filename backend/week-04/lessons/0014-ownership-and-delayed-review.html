Make a local, deliberate Git snapshot

Start at the weekly root. Inspect git status --short and git diff -- projects/task-api/src projects/task-api/tests projects/task-api/README.md. Review each intended file. Add your evidence/export/diagram paths explicitly when ready. Finally make a local commit with git commit -m "Implement Week 4 task API". These are learner actions, not actions already performed by the tutor. No push or publishing is required. Record the commit ID and why each changed module exists.

Recall at increasing delays

Now close the code and answer the four exact source prompts in assessment.md. After one or two days, reconstruct a request trace and a negative test from memory. About a week later, implement one new filter or change a title constraint, predict the affected layers and update tests/docs. Interleave a happy path, invalid payload and auth failure rather than repeating one successful POST. If recall fails, record the gap, reopen the smallest reference, retry later and disclose help used.

No new learning-records directory is created merely because content exists. The existing disclosed baseline is linked in NOTES.md. If a later session demonstrates a non-obvious skill or corrected misconception, the tutor may add a numbered record with evidence; the learner can ask for that review. Progress and attempt logs are not automatically learning records.

Explain why your test suite differs from Postman checks, why 422 differs from 409, why the service does not import FastAPI, and why restarting loses tasks. Your first independent variation should be small enough to debug but require choosing where the change belongs.
