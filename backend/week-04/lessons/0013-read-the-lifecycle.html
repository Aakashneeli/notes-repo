Read and draw the request lifecycle

Explain data flow with actual file and line evidence.

The roadmap requires a request-lifecycle note and sequence diagram. A sequence diagram shows participants horizontally and messages in time order vertically; it is not just a list of modules. Draw a successful creation and an invalid-input branch. Represent dependency resolution/validation before route execution without claiming a fixed ordering for every independent validation failure.

A worked trace for the greeting POST: curl sends JSON and badge → Uvicorn supplies the ASGI request → routing matches method/path → framework parses body and resolves arguments/dependency → badge and model checks succeed → create_greeting reads payload.name → response model permits message → JSON bytes and 201 return. Invalid body stops the route; a wrong badge stops authorized work. Our tests assert observable behavior, not private implementation order.

Read templates/request-sequence.mmd as editable diagram starter. Copy it only when ready to projects/task-api/request-sequence.mmd, a learner-created deliverable.
