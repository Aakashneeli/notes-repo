The learning path

One outcome at a time; split dense lessons across sittings. Predict, run, explain, then vary.

  1. 01Start from evidence, not a week numberIdentify the one prerequisite gap that would block database work.
  2. 02Connect to a database you can identifyStart and reconnect to a local PostgreSQL lab without confusing its data targets.
  3. 03Predict a filtered pageWrite a SELECT whose rows and order you can predict.
  4. 04Make one valid writeUse keys and constraints to keep invalid rows out of storage.
  5. 05Keep the author with no articlesExplain join cardinality and a zero-inclusive grouped count.
  6. 06Make two writes succeed togetherPredict commit, rollback and a competing write.
  7. 07Read a mapped Python classTranslate each ORM declaration into a database rule.
  8. 08Put the transaction at the boundaryUse a session without committing half an operation.
  9. 09Change schema with recorded historyInspect and apply a migration without confusing it with editing a model.
  10. 10Follow one request to durable rowsImplement the API's persistence without hiding its data flow.
  11. 11Test the failure, not only the happy pathUse a real test database and prove a partial write disappears.
  12. 12Measure an index's effectRead a basic query plan and justify one project index.
  13. 13Draw the model you actually builtConnect a schema diagram to migrations and running query code.
  14. 14Prove ownership after the hints closeCollect independent evidence and leave a reproducible project.
