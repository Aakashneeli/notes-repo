Week 05 / lesson 02

Connect to a database you can identify

Start and reconnect to a local PostgreSQL lab without confusing its data targets.

A database server is the running program. A database is a named collection inside it; a schema is a namespace inside a database; a table stores rows. A connection URL identifies a destination and a user. Before any SQL write, know which destination you reached.

This lab needs uv, Python 3.11–3.14, psql and a local PostgreSQL server. Here psql is installed but server binaries are absent. The one-container launch below is supplied infrastructure, a small prerequisite fixture rather than a Docker course. Docker must be available to your user. It uses local disk/RAM and an image download, with no cloud bill or account needed. If Docker is unavailable, have a local PostgreSQL administrator provide the same three databases and connection values; don't change system permissions blindly.

Set up once; reconnect later

Start in /home/an10/code/notes-repo/backend/week-05. Read pyproject.toml: dependencies are SQLAlchemy (SQL/ORM), psycopg (Postgres driver), Alembic (schema history), FastAPI/Pydantic (HTTP validation), uvicorn (server), httpx/pytest (checks). uv.lock records resolved versions; leave it unchanged during lessons. Run:

uv sync --locked
mkdir -p .local/postgres
docker run --name notes-week05-db -d \
  -e POSTGRES_PASSWORD=local-only -e POSTGRES_DB=w5_dev \
  -p 127.0.0.1:55435:5432 \
  --mount "type=bind,source=$PWD/.local/postgres,target=/var/lib/postgresql" \
  postgres:18.6
docker exec notes-week05-db pg_isready -U postgres -d w5_dev
docker exec notes-week05-db createdb -U postgres w5_test
docker exec notes-week05-db createdb -U postgres w5_demo

Wait for “accepting connections” before createdb. Run the launch and createdb commands only on first setup. If the container name already exists, inspect docker ps -a --filter name=notes-week05-db and use docker start notes-week05-db for your existing lab. “Database already exists” means reuse it, not reset it. If port 55435 is occupied, identify the process/container before proceeding; stop only your own obsolete verification container if appropriate. Test guards deliberately expect this port.

The bind mount keeps database files inside the ignored .local/postgres/ folder. Leave these server-managed files alone. In PostgreSQL 18's image the parent mount is /var/lib/postgresql. .venv/ is generated Python tooling, caches are rebuildable; neither is learner source. Read .gitignore before staging: data, local secrets, environment and caches must stay out of Git.

Read practice/local.env.example before sourcing it. It contains public local-only credentials, not production secrets. source runs its export commands in this shell; repeat in each new lab shell.

source practice/local.env.example
psql "$W5_PSQL_URL" -X -c 'SELECT current_database(), current_user;'
uv run python -c "import sqlalchemy; print(sqlalchemy.__version__)"

Expect w5_dev | postgres and a 2.0.x version. -X avoids personal psql startup settings. psql URLs start postgresql://; SQLAlchemy uses postgresql+psycopg:// to select its driver. Never paste the latter into psql. Quotes keep the URL one shell argument. Dev stores your project, test uses disposable schemas, demo is solely the completed migration example.

Debug before changing code

“Connection refused” means no listener at host/port; check pg_isready and docker logs notes-week05-db. “Password authentication failed” means you reached a server but credentials don't match; changing the launch environment does not reset an existing cluster's password. Missing Python module means check uv sync --locked and use uv run. A Docker socket permission error is infrastructure, not failed SQL understanding.

Record versions and destination output in the weekly log. Stop with docker stop notes-week05-db; later start and repeat SELECT. Data remains in the mount. Do not remove storage. Variation: connect to w5_test and explain the changed database name while server address stays the same. Next, query supplied temporary rows.

Primary reading: official documentation for this mechanism. Read after the worked example; the lesson supplies the reasoning you need to begin. Consult the command reference when returning after a break.
