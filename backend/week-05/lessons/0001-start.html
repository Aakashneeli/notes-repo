Three probes before setup

def rename(row, title):
    changed = dict(row)
    changed["title"] = title
    return changed

old = {"id": 7, "title": "Read"}
new = rename(old, "Write")
print(old["title"], new["title"])

Predict the output, explain what return hands back, and explain why the original stays unchanged. Then explain what a POST body and a 404 response mean. Finally predict why two separately started Python processes do not share the same dictionary.

First hint

dict(row) makes a shallow copy. These values are integers/strings, so the copied mapping can replace its title without changing old. A function call receives a return value; it does not automatically print it.

Check and reasoning

The output is Read Write. POST commonly submits new data in a request body; 404 means the requested resource was not found. Each process has its own memory. A shared database gives both processes a common storage service, but they still need concurrency rules.
