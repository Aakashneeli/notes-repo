Draw the model you actually built

Connect a schema diagram to migrations and running query code.

An entity-relationship diagram explains stored structure. A request sequence explains behavior over time. Don't mix them into one drawing with unlabeled arrows. For this week's deliverable draw tables, fields, keys and cardinality, then use a written trace to connect an endpoint to its queries.

Practice reading a relationship

For the supplied SQL sample, authors has id as its primary key. articles.author_id is a nullable foreign key to it. One author can have zero or many articles; one article can have zero or one author. The nullable reference explains Draft without inventing an “Unknown” author row. A join does not create this rule; the schema does. This example diagram is only a reasoning rehearsal; the deliverable must reflect your Task tables.
