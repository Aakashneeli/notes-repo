Week 05 / lesson 07

Read a mapped Python class

Translate each ORM declaration into a database rule.

An ORM maps Python objects to relational rows. It doesn't remove SQL: attributes become column values, a query becomes SQL, and constraints still run in PostgreSQL. This week chooses SQLAlchemy 2.0, one of the source's allowed paths. Pydantic describes accepted/returned HTTP data; an ORM class describes persistent storage. Keeping those roles separate helps you notice rules that must exist in both layers.

From the weekly root read practice/orm_example.py, a completed label example unrelated to the Task project. Focus first on its declarations:

class Base(DeclarativeBase):
    pass

class Label(Base):
    __tablename__ = "example_labels"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(40), unique=True)

class Label(Base) inherits the mapping behavior registered by Base. __tablename__ names the SQL table. The annotation Mapped[int] says this attribute is managed by the ORM and holds an integer. mapped_column adds storage options. Non-optional mapped types infer NOT NULL here; the primary key also forbids NULL. String(40) describes a length bound in PostgreSQL. SQLite does not enforce this length identically; the teaching example is not a backend-compatibility test.

Base.metadata collects table descriptions. It is a Python description, not the actual database. Editing the class does not modify an existing table. The example uses create_all solely to construct a disposable in-memory sample. The persistent project must use migrations instead.

Express a rule and a reference

# Focused excerpt for an unrelated Article model:
author_id: Mapped[int | None] = mapped_column(ForeignKey("authors.id"))
__table_args__ = (
    UniqueConstraint("title", name="uq_articles_title"),
    CheckConstraint("length(trim(title)) > 0", name="ck_articles_title"),
)

This excerpt belongs inside a mapped class with a title column and an existing mapped authors table; it is not a standalone program. The string authors.id identifies table.column. None permits an unassigned article; removing None requires a reference. The tuple groups table rules, and its commas separate objects. Constraint names make migration changes and precise error handling possible. A CHECK on title still needs NOT NULL on the column if missing text is forbidden.

Object navigation can be added with articles: Mapped[list["Article"]] = relationship(back_populates="author") on Author and author: Mapped["Author | None"] = relationship(back_populates="articles") on Article. Import relationship from sqlalchemy.orm. The quoted forward name lets a declaration refer to a class defined later. back_populates names the attribute at the opposite end, not a table. A list means many related objects. Accessing a relationship may execute another SELECT, so don't rely on lazy loading after closing the session. See the official relationship patterns for the complete declaration context.

Trace object to row

Label(name="draft") first creates a Python object. session.add(item) schedules it for persistence. After flush, the INSERT has run and its generated ID is available. Before flush, you must not assume the ID exists. Closing Python loses that object; a later SELECT can reconstruct another object representing the same stored row.

Transfer to your tables

Read the project contract and models.py. It supplies only Base; you implement Task and TaskEvent. Draw a small row example on paper before declaring attributes. A task can have many events; each event references one task. The database foreign key and an ORM relationship are distinct: a ForeignKey enforces references, while relationship gives convenient object navigation. You can query with explicit joins even before adding relationship navigation.

Vocabulary for your implementation: import ForeignKey, CheckConstraint and UniqueConstraint from sqlalchemy. A table-level __table_args__ tuple holds named rules. ForeignKey("tasks.id", ondelete="CASCADE") is one possible deletion policy; justify it before use. An annotation such as Mapped[str | None] permits NULL unless explicitly overridden. Choose required fields deliberately; a default is not a substitute for NOT NULL.

Check: what survives a model edit?

The existing table keeps its old structure until migration SQL changes it. Autogeneration compares metadata and database; it doesn't mean “the class was saved, therefore schema is updated.”
