Keep the author with no articles

Explain join cardinality and a zero-inclusive grouped count.

A relationship is stored as values: articles.author_id refers to authors.id. A join uses that match to produce combined rows. If Asha has two matching articles, her name appears twice. This isn't unwanted duplication caused by SQL; it is the result's one-row-per-match shape.

SELECT a.name,b.title
FROM authors AS a
JOIN articles AS b ON b.author_id=a.id
ORDER BY a.id,b.id;

AS a and AS b are aliases, short names within this query. a.id means the author's ID, not the article ID. Match Asha to 1 and 2; match Ben to 3. Chen has no match; Draft has no author. The inner join returns three rows. Missing ON can create a cross product—every author paired with every article—which changes both results and counts.

Trace LEFT JOIN before counting

SELECT a.name,count(b.id) AS n
FROM authors AS a
LEFT JOIN articles AS b ON b.author_id=a.id
GROUP BY a.id,a.name
ORDER BY a.id;

The left join keeps every author. Before grouping its rows are Asha/1, Asha/2, Ben/3, Chen/NULL. GROUP BY collects each author's matches. COUNT(b.id) counts non-NULL IDs: Asha 2, Ben 1, Chen 0. COUNT(*) counts result rows instead and gives Chen 1 because the placeholder row exists. Group by the stable author key as well as name so two equal display names wouldn't be merged accidentally in another schema.

WHERE filters rows before grouping; HAVING filters groups after aggregation. Add HAVING count(b.id) >= 2 before ORDER BY to keep Asha alone. Do not write aggregate count in WHERE; that stage doesn't yet have the grouped count.

A subtle failure

Adding WHERE b.published=true to a left join removes Chen: the synthetic NULL row doesn't satisfy the filter. To count published articles while preserving all authors, move this condition into ON: ON b.author_id=a.id AND b.published=true. Matching is restricted before the left join adds an unmatched author row. Expected counts are Asha 1, Ben 1, Chen 0.
