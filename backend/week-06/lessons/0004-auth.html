Week 06 / Lesson 04

Make access fail closed

Implement a dependency that rejects missing and invalid keys without leaking secrets.

Authentication checks a credential; authorization decides what that identity may do. This local single-tenant lab uses one shared API key for both routes. It does not establish per-user document ownership. A real multi-tenant service would check ownership on every job lookup as well.

Read .env.example, then create your own ignored .env only if it does not already exist. Its key is an intentionally public local placeholder. Settings.from_env() reads environment variables, not a file automatically; an empty key raises ValueError rather than enabling anonymous access. The dataclass stores settings, frozen=True prevents ordinary reassignment and repr=False keeps the key out of its printable representation. That is one narrow safeguard, not universal redaction.

header = APIKeyHeader(name="X-API-Key", auto_error=False)
# In practice/examples.py:
def authorized(value=Depends(header)):
    if not matches(value, "demo-only"):
        raise HTTPException(401, "Invalid API key")

Depends asks FastAPI to call the header extractor before the handler. auto_error=False gives your dependency control of the missing-key response. Missing becomes None; comparison fails; 401 stops the handler. A valid value allows execution. Explicit status handling keeps this lab independent of changing framework defaults. The demo compares encoded bytes with secrets.compare_digest; it first rejects absent/empty values.

Secrets and logs

Use the OWASP secrets guide to check the exposure/rotation reasoning below.

Use headers, never URL query parameters, for keys. URLs often enter histories and access logs. Do not log complete requests, settings, document bytes or arbitrary exception text.
