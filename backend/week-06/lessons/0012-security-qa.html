Week 06 / Lesson 12

Probe the boundary as a client

Distinguish CORS, authentication and rate limiting, then test uploads manually.

CORS is a browser policy about which origins can read responses across origins. An origin includes scheme, host and port. The supplied app permits http://localhost:3000 with GET/POST and named headers. A browser may send OPTIONS first for a custom API-key header. CORS middleware answers that preflight. It does not authenticate a client; curl and another backend are not protected by browser CORS enforcement.

Rate limiting answers how much work a caller may request. Place coarse connection/body controls at ingress and authenticated per-key quotas before costly ingestion. Return 429 and a meaningful retry policy; account for bursts and shared identities. A per-process dictionary splits counts across workers and resets on restart. A shared Redis counter can coordinate counts but needs atomic window operations and an outage policy. This week's requirement is awareness and a justified design note, not a production limiter.

Start your completed local project

From the weekly root, use the deliberately public local key below. These commands set shell environment variables; app.py does not auto-read .env. Runtime/dev contains generated private blobs and metadata; retain it to test restart persistence. Do not commit it.

cd /home/an10/code/notes-repo/backend/week-06
export INGEST_API_KEY=local-study-only
export INGEST_ROOT=runtime/dev
uv run uvicorn ingestion.app:create_app --factory --app-dir projects/ingestion --host 127.0.0.1 --port 8006

Leave the server open. In another terminal start at the weekly root. Read the harmless supplied projects/ingestion/data/hello.txt and invalid.html; leave both unchanged so expected outputs stay reproducible.

cd /home/an10/code/notes-repo/backend/week-06
curl -i -F "file=@projects/ingestion/data/hello.txt;type=text/plain" http://127.0.0.1:8006/documents
curl -i -H "X-API-Key: local-study-only" -F "file=@projects/ingestion/data/hello.txt;type=text/plain" http://127.0.0.1:8006/documents
curl -i -H "X-API-Key: local-study-only" -F "file=@projects/ingestion/data/invalid.html;type=text/html" http://127.0.0.1:8006/documents

Expect 401, then 202 with a job_id, then 415. Poll curl -i -H "X-API-Key: local-study-only" http://127.0.0.1:8006/jobs/JOB_ID, replacing JOB_ID. hello.txt includes its final newline: completed has characters=34 and words=5. Save sanitized responses in weekly-logs/week-06.md. Stop with Ctrl-C, rerun the same server command and fetch the same ID; metadata should persist. This demonstrates a graceful restart, not crash recovery of active jobs.

Postman deliverable

The Postman form-data guide supports the local steps below.

Import projects/ingestion/postman/week-06.collection.json and local.environment.json. These supplied local templates contain no real credential. Select that environment; set api_key locally to the same teaching key. For each upload request choose the local file from the file picker: exported file paths are not portable. Let Postman generate the multipart Content-Type boundary; do not hand-set it. Successful upload tests save job_id in the environment. Run auth failure, invalid file and job status requests as well. Update the collection with at least one additional edge case and export a sanitized copy over the starter only after retaining your edits.

Fill projects/ingestion/security-checklist.md with evidence for auth, validation, secrets, paths, logs, CORS and limiter placement. Separate what you tested from design-only controls. Do not mark production-safe: parser resource controls, multi-tenant ownership, malicious document analysis and durable scheduling remain outside this small local implementation.
