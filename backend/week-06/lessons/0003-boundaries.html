Week 06 / Lesson 03

Give each layer one responsibility

Follow data through the package without mixing HTTP, policy and storage.

Low-level design here means deciding which small module owns a change. A router converts HTTP inputs and outputs. A schema describes allowed data. A service coordinates a use case. A repository reads and writes durable metadata. An integration talks to a filesystem or queue. These boundaries let you change storage without rewriting authentication or extraction rules.

HTTP multipart file
  -> routes: authenticate; parse UploadFile
  -> validation: bounded bytes or upload error
  -> service.accept: choose ID; save bytes; create metadata
  -> storage.put + repository.create
  <- job ID
  -> BackgroundTasks: schedule worker with ID
  <- 202 {job_id, state: "pending"}

For a tiny note, the route sees request headers; the storage adapter sees only a trusted generated key and bytes. The worker later receives a job ID and retrieves the saved key. It never needs the API key or a live request object. Passing an UploadFile to later work is tempting, but its request lifetime is the wrong ownership boundary.

Read projects/ingestion/README.md for the contract. In projects/ingestion/ingestion/, __init__.py marks the package; relative imports such as from .config import Settings select a sibling module. Read supplied app.py: its factory wires a Repository, LocalStorage and router once per app. A factory is a function returning an application, useful when tests inject temporary settings.

Read the TODO contracts in routes.py, schemas.py, service.py, auth.py, validation.py, storage.py and worker.py; you will edit them progressively. Read config.py and repository.py as supplied bridges. The folder names are a navigation aid, not proof of good separation.

Failure and independent variation

A service raising FastAPI HTTPException couples worker execution to HTTP. Keep HTTP translation at the route. Place a proposed S3 client in an integration, then name the methods its caller should keep using. Do not implement S3 this week.

First hint

Think about the caller: it needs bytes stored or read, not bucket configuration.

Explained beginner answer

A storage adapter can preserve put/read/delete while the service retains its orchestration. In design.md explain how identifiers and failure behavior stay stable; matching method names alone is not enough.

Primary reading: fastapi.tiangolo.com — relevant official guide. See annotated sources for supporting API and security documentation.
