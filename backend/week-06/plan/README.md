# Flexible sequence

1. Lesson 1: answer baseline probes; take only necessary linked refreshers.
2. Lessons 2–4: environment, boundaries and access. Stop when you can trace the auth dependency.
3. Lessons 5–7: bytes, safe storage and durable metadata. Practice exact boundary failures.
4. Lessons 8–9: states and background lifetime. Implement worker after tracing failure paths.
5. Lesson 10: required Redis/RQ concepts and migration note; optional dedicated local queue.
6. Lesson 11: assemble learner implementation and contract tests in small slices.
7. Lesson 12: terminal/Postman QA, restart persistence, security evidence.
8. Lesson 13: code reading, independent explanation, regression/variation and Git review.
9. After about two days and one week: delayed retrieval using the review template.

Split any lesson at a heading if needed. No fixed number of sittings. Revisit an earlier
mechanism only when your evidence identifies a gap. When stuck: prediction → smallest
reproduction → one hint → attempt again. Keep outcomes and assistance in the weekly log.
The file map, coverage and assessment are tutor-maintained planning tools, not completion records.
