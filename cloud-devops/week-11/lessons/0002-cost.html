Week 11 · 02

Price a bounded experiment

Calculate an all-in estimate and explain why an alert cannot cap spending.

A cloud bill is accumulated usage, not simply “one server.” A compute rate multiplies running hours; disks continue storing data when the process stops. Networking, registry storage and logs have separate meters. The $20/month constraint belongs to the whole experiment, including any other services it uses.

Work the units

Use hypothetical rates, not price quotes: 100 hours × ($0.010 compute + $0.005 IPv4) + $1 storage + $0.50 logs + $2 reserve = $5. At 730 hours the same assumptions give $14.45. Changing planned runtime affects hourly components, but not the fixed monthly allowances. A “free tier” is account-specific; credits can expire. Estimate without credits first.

Guided calculation

Edit only monthly_total in practice/exercises.py. Its six inputs are ordinary numeric values in consistent units. Reject any negative input with ValueError; otherwise return the computed total. The supplied test_exercises.py checks arithmetic, zero running hours and invalid input.

.venv/bin/python -m pytest practice/test_exercises.py -k total -q
Hint 1 — separate the rates from amounts

Only compute_hourly and ipv4_hourly multiply hours. storage, logs and reserve are already money amounts.

Hint 2 and explained beginner answer
values = (hours, compute_hourly, storage, ipv4_hourly, logs, reserve)
if any(value < 0 for value in values):
    raise ValueError("negative input")
return hours * (compute_hourly + ipv4_hourly) + storage + logs + reserve

The generator asks the same yes/no question of every input. any detects one invalid value. This simple calculator does not model tiered prices, tax or per-second rounding.

Turn the estimate into a decision

Open cost-plan.md. For your region record pricing date, Linux/architecture/type, planned hours, EBS capacity, public IPv4, ECR, CloudWatch, transfer and reserve. Add S3/database only if selected. Use the linked EC2/VPC pricing and AWS calculator; save the inputs, not just a total. Avoid guessing a universal cheapest instance or assuming a small instance can hold the entire AI stack.

Learner cloud action, before launch: in Billing → Budgets create a monthly cost budget for $20 with actual-spend alerts at $5/$10/$15 and a forecast alert at $20. Confirm the recipient and budget scope includes the experiment's services; record confirmation without personal details. Alerts arrive after usage information is processed. They do not stop the server. Choose a review time and a shutdown trigger with headroom; if the estimate exceeds the constraint, shorten the experiment or stay local.

Do not add a NAT gateway or load balancer casually: each introduces separate pricing. No budget is created by this lesson. Check: can you point to every cost category and explain what survives a stopped server? Next: limit who can operate it.

Primary sources

  • EC2 pricing — Region/type billing inputs; verify before spending.
  • VPC pricing — Public IPv4 and optional networking charges.
