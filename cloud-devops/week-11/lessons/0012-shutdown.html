Week 11 · 12

Close the experiment and prove ownership

Create a resource-specific shutdown record and complete delayed retrieval without inventing mastery.

A stopped API is not a zero-cost account. The resource inventory is your map from intention to bill. EC2 stop preserves disks; termination can delete attached storage according to its settings. Snapshots, retained volumes, registry images and log groups can remain. RDS temporary stop is not permanent shutdown: it automatically restarts after the supported stop period (currently seven days), and storage still matters.

Inspect before removing

At the week root open shutdown.md. Add the exact resource IDs, regions, data-retention decision, owner and verification time for each item you created. Use the console inventory in every region used; do not rely only on the instance list. Include EBS volumes/snapshots, public/Elastic IPs, ECR, CloudWatch groups, conditional S3/RDS, and any accidental NAT/load balancer. Include external DB/provider/GitHub charges if used.

Learner cloud actions: stop the host for a short pause only if the remaining cost is acceptable; for final removal first decide whether data/backups must be retained, then terminate only the identified lab instance and inspect attached volumes and addresses. Delete only chosen unneeded resources, preserving required data. In versioned S3, delete markers do not remove retained versions; check versions and incomplete multipart uploads. Stop/scale-down compute in other services too if you created it. Do not blindly delete all resources in an account.

Confirm resource state immediately, then recheck billing after its reporting delay on the next day and later in the billing period. Record remaining costs and next review date. An empty EC2 running list is not proof of a zero bill. Budget alarms are still useful after shutdown.

Rehearse the reasoning locally

Scenario: you stop one EC2 host with an EBS volume and retained logs; your forecast is still increasing. Predict which line items to inspect. Write a three-line inventory with a keep/delete reason and one observation that would falsify your guess.

Hint and feedback

Separate running compute from retained storage and any allocated addresses. A volume's existence can explain continued storage cost; it cannot explain a running NAT gateway charge. Check the service/region in billing rather than repeatedly restarting the API.
