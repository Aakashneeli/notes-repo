Week 11 · 06

Inject configuration without baking secrets

Trace a secret from its source to the process and rehearse a safe configuration failure.

An environment variable is a name/value available to a process. It is a delivery mechanism, not a secure storage system. A container image should be reusable across environments; its runtime configuration chooses behavior. API_KEY is sensitive; RELEASE is a public identifier; FAIL_MODE is a training fault switch and should be empty normally.

A configuration trace

Docker reads an env file → creates the container with those variables → Python reads os.getenv → ready decides whether API_KEY exists. Editing the file later does not update the running process. Restarting an existing container retains its creation-time environment; recreate it with the new settings. A blank key causes 503, which is safer than silently disabling authentication.

Read .env.example. Its values are public dummy inputs. At the week root, copy it only if you have no existing .env:

cd /home/an10/code/notes-repo/cloud-devops/week-11
cp -n projects/deployment/.env.example projects/deployment/.env
chmod 600 projects/deployment/.env
git check-ignore projects/deployment/.env

-n avoids overwriting an existing learner configuration. Use your editor to change RELEASE to rehearsal-two and blank API_KEY for the local failure exercise; keep only dummy values. Expect git check-ignore to print the path. If a real secret was previously committed, ignoring the file does not undo exposure: revoke/rotate it, then follow the repository's history-remediation process.

Stop the previous lab container, recreate with --env-file projects/deployment/.env and repeat health/ready requests from lesson 4. Expect a new release and 503 readiness. Restore the dummy key, recreate, and observe 200. Save only statuses and variable names in weekly-logs/week-11.md.

Live ownership choices

For the private EC2 lab, a host file with mode 600 outside the source checkout is an explicit minimal choice; the host administrator and Docker daemon can read its values. Docker inspection can expose environment values, so do not paste raw inspect output or enable shell tracing. A managed alternative is SSM Parameter Store SecureString or Secrets Manager: an authorized startup step retrieves a named secret using a role, then injects it. The API still sees the value; managed storage improves access/auditing/rotation, not immunity from a compromised process.

Keep AWS access keys out of the app environment. An EC2 role supplies temporary AWS identity to host services; application containers needing AWS access require deliberate credential delivery. Do not assume an IMDSv2-required host automatically makes credentials reachable from a bridge container. For this fixture, only the host logging daemon needs AWS identity.

Edit secrets.md: source of truth, reader, delivery point, rotation and revocation for each variable. A GitHub secret is a separate copy with a separate update lifecycle; masking is not permission to print it. The deployment lesson will keep secret creation a learner action.

Explain-back feedback

“The secret is in .gitignore” answers a repository question, not where it lives or who can read it. A complete answer names the host/managed store, permissions, injection time, runtime access and replacement procedure.

Variation: rotate the dummy key; show the old key gets 401 and the new key 200 after recreation. Next: choose what data, if any, must outlive the container.
