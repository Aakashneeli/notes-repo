Feedback and targeted refreshers

The mapping binds host loopback port 8000 to container port 8000. A 401 concerns authentication; 500 is an unexpected server failure; 503 means unavailable. A process can run while its required configuration or dependencies are unavailable. If unfamiliar, read only the needed image, network, health, or HTTP refresher.

Prepare one local environment

Start in the repository, then enter this week. pwd confirms command context. uv venv creates an isolated dependency directory, and uv pip sync installs the tutor's exact lock. Python 3.12, uv and package-download access are needed; no GPU or AWS key is needed. If .venv already exists, inspect its Python version before syncing; use a separate environment if it contains your unrelated work.

cd /home/an10/code/notes-repo/cloud-devops/week-11
pwd
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python requirements.lock
.venv/bin/python -m pytest projects/deployment/fixture -q

requirements.in lists direct dependencies: FastAPI routes, Uvicorn server, HTTPX client, pytest checks, Ruff lint and PyYAML configuration parsing. requirements.lock pins their transitive dependencies too. Read these; don't independently upgrade one package mid-lab. .venv/, __pycache__/ and test caches are generated infrastructure, not study assignments. .gitignore excludes them, local secrets and generated artifacts.

Read pyproject.toml: pytest's pythonpath locates the fixture, practice and release modules; testpaths selects learner checks. Ruff checks imports and core syntax/name errors. These settings make commands reproducible from this root. Tutor-only maintenance/test_examples.py tests completed examples; maintenance/verify.py checks local links, anchors, Python syntax and file-map coverage. Run .venv/bin/python maintenance/verify.py only when auditing materials; leave these tools unchanged during learning. See VALIDATION.md for the actual results and limits.

In this prepared checkout, the tutor's Python 3.12 runtime is under ignored generated/python/, and .venv uses it. Leave it unchanged; it is generated tooling, not project source. A fresh clone uses the uv setup commands above to obtain its own interpreter. If you move this workspace, recreate .venv against the new interpreter path rather than assuming its absolute links still work.

Trace the bridge

Read projects/deployment/README.md, then fixture/app.py. Imports bring in environment access, timing, UUIDs, logging, FastAPI routes and JSON responses. A decorator such as @app.get("/health") registers a function as a handler. The middleware runs around every request: generate ID → start timer → call route → sanitize an unexpected exception → emit safe event → attach ID. await yields while the asynchronous route machinery runs. The key comparison uses constant-time comparison; it never logs the key. This is a small deployable fixture, not a finished AI backend.

With API_KEY absent: health is 200, ready is 503, message is 503. With a key: ready becomes 200, but message without the header is 401. The supplied fixture tests set temporary environment values using pytest's monkeypatch; TestClient calls the app without starting a network server. Read and run them, leave their contract intact. Passing proves these routes, not Docker or cloud access.
