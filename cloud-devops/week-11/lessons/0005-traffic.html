Draw the private traffic path

Locate a failed request at the network, host or application boundary.

The affordable teaching path is one EC2 host reached through SSH, with the API published only on host loopback. “Private endpoint” here means access-controlled through a tunnel; the host may still have a public IP for SSH. It is not an AWS PrivateLink endpoint or a VPC-private subnet design.

Follow one byte

laptop curl 127.0.0.1:18000
  → laptop SSH tunnel
  → internet → EC2 public IP:22 (SG permits your IP only)
  → SSH server → EC2 loopback:8000
  → Docker port mapping → container:8000
  → Uvicorn → FastAPI route

A VPC is the network boundary; a subnet owns a range of addresses. For this simple public-host path, the subnet route table needs an Internet Gateway route, and the instance needs a public address. A route says where to send packets; the security group says which traffic is allowed. Network ACLs and host firewalls can also affect delivery. We use the default network ACL rather than introducing another lab configuration.

SSH encrypts the tunnel. The HTTP connection inside it is not a public HTTPS service. No inbound 8000 rule is needed. A true public API would instead need a public HTTPS entry point, certificate/domain handling, authentication and appropriate proxy/host controls; do not open 8000 globally as a substitute. This week's source permits a documented private endpoint.

Predict failures before changing rules

If SSH times out, inspect instance state/address, source-IP rule and route. If SSH says permission denied, the TCP connection reached SSH; check username/key. If the tunnel connects but curl is refused, inspect Docker publishing and server startup. If curl returns 401, the network worked; inspect authentication. If it returns 500, use the request ID and logs.

Guided observation without AWS

Expect a loopback mapping and safe request events. No AWS result can be inferred. In access-plan.md finish the port/source table; in weekly-logs/week-11.md write which failure layer a 401 and a timeout implicate.

Hint and feedback

A timeout supplies no HTTP response, so start below the route handler. A 401 proves some HTTP server answered, but check the release too: it could be the wrong service on that port.
