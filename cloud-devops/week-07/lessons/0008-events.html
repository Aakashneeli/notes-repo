Week 07 / Lesson 08

Write logs a tool can read

Create a safe JSON event and explain how it travels to a log reader.

A log event describes one observation. Structured logging gives stable field names and value types so tools can filter by status or request ID. JSON is a serialization format: a Python dict becomes one text line using json.dumps, and a reader can reconstruct its fields using json.loads. A dict's printed representation uses Python syntax and is not reliably JSON.

Trace a record through a handler

Read event_line in practice/mechanisms.py. From Week 7 run it again and predict the type of its result: str, not dict. The example field status is a number, so a consumer can compare it numerically. A Python logger creates records; its level filters them; a handler chooses the destination; a formatter decides which text surrounds the message.

import json
import logging
import sys
logger = logging.getLogger("lesson.events")
logger.setLevel(logging.INFO)
handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(logging.Formatter("%(message)s"))
logger.addHandler(handler)
logger.info(json.dumps({"event": "lesson", "status": 503}))

Expected output is {"event": "lesson", "status": 503} on one line. This completed fragment emits one JSON object to stdout. The message-only formatter avoids prefixes that would break a JSON-lines parser. Repeatedly adding handlers duplicates output, so application setup should add its handler only once. Logger propagation can help pytest's caplog capture records; keep that capture working while avoiding duplicate application handlers. INFO is often filtered unless you set a level.

Use an allowlist

Edit safe_fields in practice/exercises.py. Return a new dict containing only event, request_id, status keys that exist. Never log whole request headers, query strings, upload bodies, connection URLs or exception text. A denylist misses a newly added secret field; an allowlist omits it automatically.

.venv/bin/python -m pytest -q practice/test_exercises.py -k allowlist
Hint · open after trying

Iterate over allowed key names and copy a value only if that key exists.

Explained answer · compare your reasoning

A worked answer is return {key: event[key] for key in ("event", "request_id", "status") if key in event}. This comprehension constructs a new dict; it neither deletes fields from the input nor guesses which secret keys might arrive.

Local destination, later cloud destination

Your project logger will be week7.http. Configure stdout once in observability.py, then implement the request wrapper in Lesson 9. Locally Docker captures stdout/stderr and docker compose logs api displays them with optional service prefixes. Those prefixes are Compose's display, not fields in your JSON. Use --no-log-prefix for machine inspection. Uvicorn/RQ/library logs may still have other formats; the required structured stream here is week7.http.

In AWS a configured container logging driver/agent can route the same stdout events to CloudWatch. Delivery, retention, access and cost become explicit deployment configuration; printing JSON alone does not configure that route. No AWS action is needed this week. Note this boundary in decisions.md and proceed to correlating individual requests.
