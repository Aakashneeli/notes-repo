Run the prerequisite fixture checks

Trace the supplied ingestion bridge without treating it as your completed earlier project.

Week 6 has unimplemented orchestration and workers. We preserve it. This week's projects/local-stack/fixture/ is a deliberately smaller prerequisite: raw UTF-8 text, up to 4096 bytes, stored in PostgreSQL and processed by an RQ worker. It omits multipart file storage, migration history, comprehensive job recovery and production auth. You implement the Week 7 operational layer around it.

Prepare a reproducible Python environment

Starting at the Week 7 root, read requirements.in, requirements.lock and pyproject.toml. The first lists direct dependencies, the second fixes resolved versions, and the third tells pytest where modules live and Ruff which errors to check. Leave them unchanged initially. FastAPI/Starlette route requests; Uvicorn serves them; httpx tests HTTP; psycopg connects SQL; redis/RQ queue work; pytest/Ruff check code; PyYAML reads configuration for our checker.

If your machine lacks Python 3.12, install that interpreter through your existing approved toolchain first. The author environment may already exist; reuse it if .venv/bin/python --version reports 3.12. Do not recreate it over a working environment. If pip is missing from an existing uv-created environment, use uv pip sync --python .venv/bin/python requirements.lock. Network access is needed only to obtain packages. The prepared author environment uses a repository-local Python interpreter under ignored artifacts/python/. Leave that generated runtime alone; a fresh clone needs its own interpreter for host-side checks. A virtual environment is generated software, not lesson content; caches and bytecode can be ignored. .gitignore keeps these and local .env out of Git.

Expect seven author/example tests to pass, then 503 and a JSON line. This checks supplied Python mechanisms, not Docker or project completion. Read practice/mechanisms.py and its tests: dictionaries label values; all requires every value true; json.dumps serializes to text. The explicit empty check prevents an empty dependency set claiming success.

Follow one supplied request

Read fixture/api.py, then core.py. The router groups endpoints. The dependency compares the key before accepting data. async for reads body chunks with a size guard. await run_in_threadpool(...) gives synchronous database work to a thread instead of blocking the event loop. A with connection() block commits on success and rolls back on an exception; SQL values go through parameters.

  1. POST text → validate → make an ID.
  2. Commit a pending row → enqueue the importable name fixture.core.extract plus ID.
  3. A separate RQ worker imports the same package, locks the row and counts text characters.
  4. GET status queries the shared row. An API-process dictionary would not be visible to the worker.

__init__.py makes the package explicit. bootstrap.py creates this lab's table before serving; it is not Alembic. maintenance/test_fixture.py injects a memory backend to test validation without services. Leave these supplied files unchanged unless diagnosing a documented fixture defect.

Failure and variation

Database commit and queue enqueue are not one transaction. If enqueue fails, this bridge attempts to mark the row failed and returns 503; a crash between the two can leave pending work. It has no outbox or retry recovery. Predict how the status differs from completed work, and record this limitation in the weekly log. Read the project contract and bridge-notes.md; fill the latter with the path you chose. You may later adapt a completed Week 6 implementation in a separate copy, after explaining its real tests and storage needs.

Primary reading: www.psycopg.org · official documentation. Use it to check this mechanism, then return to your own example.
