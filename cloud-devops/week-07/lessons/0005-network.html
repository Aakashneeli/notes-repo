Week 07 / Lesson 05

Let services find each other

Choose an address from the caller’s location and wire the five service boundaries.

Compose turns a YAML service description into containers and networks. YAML mappings use key: value, indentation nests keys, and a dash starts a list item. Use spaces, not tabs. A service name becomes a DNS name on its shared network. The address to use depends on who is calling.

Trace the two sides of a port

Browser → 127.0.0.1:8077 on the host → published port → API port 8000. API → postgres:5432 on the container network. A host port is unnecessary for API-to-database traffic. From the API, localhost:5432 asks for Postgres inside the API container and normally fails.

From Week 7, read the completed practice/two-services.yaml. It starts a cache and a client that runs redis-cli against the name cache:

docker compose -f practice/two-services.yaml up -d cache
docker compose -f practice/two-services.yaml run --rm client
docker compose -f practice/two-services.yaml down

Expect PONG after Redis starts. If the first attempt sees connection refused, wait for its startup log and repeat the client command; this is the startup race Lesson 6 fixes. The example has no named data volume to preserve. Record who resolved cache and why no port was published.

Hint · open after trying

Return a two-item tuple in each recognized branch; reject other locations explicitly.

Explained answer · compare your reasoning

Use if location == "host": return ("127.0.0.1", 8077); elif location == "worker": return ("api", 8000); else: raise ValueError(location). The worker sees service DNS, the host sees the published socket.

Write your own stack topology

Edit projects/local-stack/compose.yaml. Read service-contract.md for every image, command, address and volume target. Start with postgres and redis, then api, worker and vector. Read .env.example; it contains only public disposable lab defaults. Environment interpolation happens in Compose on the host. Variables reach a container only if you map them with environment or env_file.

A minimal unrelated service fragment illustrates the syntax:

services:
  web:
    image: example-web:local
    ports:
      - "127.0.0.1:${WEB_PORT:-8080}:8000"
    environment:
      CACHE_URL: redis://cache:6379/0
    networks: [front, data]
networks:
  front: {}
  data:
    internal: true

${WEB_PORT:-8080} means use WEB_PORT or default 8080. In your lab, use API_PORT and the documented 8077 default. internal: true isolates that network from external connectivity; it does not stop services on it from talking to each other. Only api joins both app and data networks; other services join data. Do not publish database, queue or vector ports. The Docker host remains a privileged boundary.

cd projects/local-stack
docker compose --env-file .env.example config --quiet
docker compose --env-file .env.example config --services
cd ../..
