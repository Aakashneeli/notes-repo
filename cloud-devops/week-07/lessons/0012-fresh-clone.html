Week 07 / Lesson 12

Make the start path reproducible

Prove a documented start command without relying on hidden local files.

A fresh clone has tracked source and configuration examples. It does not have your .venv, cached images, local .env, stopped containers or named-volume state. One documented Compose command can build and start services after Docker/Compose and network prerequisites are met. It cannot compensate for an unfinished Dockerfile or hidden dependency.

Write a short operator runbook

Open runbook.md. Fill its start directory, prerequisites, one command, sample check, stop-with-data-preserved command, expected ports and troubleshooting pointer. The intended starting directory is notes-repo/cloud-devops/week-07/projects/local-stack, with:

docker compose --env-file .env.example up --build --wait --wait-timeout 120

That is the target command after implementation, not a claim that today's comments-only starter is runnable. Its build context ../.. includes requirements.lock and runtime source. The public .env.example removes a hidden setup dependency for this loopback-only disposable lab. If you change that design, document your explicit prerequisites and make the contract still reproducible.

The author leaves all Git staging/history untouched. Learner action when ready: stage only reviewed Week 7 paths, inspect the scoped cached diff again, and commit only when the index contains exactly the intended work. Do not push as an exercise requirement.

A local clone sees commits, not uncommitted working files. After your assessed work is committed, choose a new unused destination inside this repository's ignored artifacts directory and a new Compose project name, so existing volumes are untouched. The fresh-clone procedure lives in runbook.md; do not reuse a destination with saved evidence. Record the commit, daemon/Compose versions and whether images were cached. A clean checkout can still benefit from the machine's image cache; disclose that rather than claiming a fully cold build.

Review network boundaries

Finish architecture.mmd: draw host-to-api ingress, app/data networks, service-name arrows, and named-volume attachments. Vector has no ingestion arrow beyond its placeholder probe. Worker consumes Redis and updates Postgres; it is not called by the browser. In decisions.md explain why only one port is published and why this lab lacks TLS, hardened secret distribution and high availability. Those are practical limits, not hidden completion criteria from future weeks.

Independent variation: from the fresh copy use a free alternate host port and prove a job completes without changing the application image. Record a prediction, observed result and the exact starting directory. Return to Week 7's desk for final retrieval.
