Week 07 / Lesson 03

Build once, run twice

Predict which values belong to an image and which belong to one running container.

An image packages filesystem content and startup defaults. A container runs a process from it with its own writable layer and runtime settings. Building prepares the package; running starts the process. An exited process leaves a stopped container unless removed. A Python virtual environment isolates packages; it does not supply Docker's process and network isolation.

One complete example

From the Week 7 root, read practice/tiny-image/Dockerfile, hello.py and .dockerignore. These are completed teaching files. FROM selects Python; WORKDIR sets the inside path; COPY transfers source; CMD names the default runtime process. The ignore file excludes local secrets and bytecode from the build context.

docker version
docker compose version
cd practice/tiny-image
docker build -t week7-hello:lesson .
docker run --rm week7-hello:lesson
docker run --rm -e LESSON_NAME=builder week7-hello:lesson
cd ../..

The first run prints hello reader; the second hello builder. Same image, different environment. -t names the image; the final dot supplies the context directory; --rm removes only that completed example container; -e sets one runtime variable. Record image ID and both predictions/results in the weekly log. Next, write your project Dockerfile in Lesson 4.

Docker needs a running daemon, sufficient local disk/RAM, and image-download access. These small services require no GPU or model-provider credentials; memory use varies, so inspect it rather than assume a fixed minimum. Docker Engine use here provisions no paid services. Desktop users must check their organization's license terms. If docker version shows only Client or permission denied, no image exercise has run. Record the exact error, consult your existing local Docker setup, and continue Python lessons while daemon setup remains a learner action. Do not change socket permissions to make the symptom disappear.

Trace the failure

Edit hello.py to change the greeting in this disposable example. Predict whether running the old image changes. It does not: COPY happened during the earlier build. Rebuild the same tag, run again, then inspect docker image inspect week7-hello:lesson --format '{{.Id}}' from this same example directory. Save the before/after observation. A tag is a movable name; a digest identifies content.

Hint · open after trying

Ask whether the running process reads your host source file or the image copy.

Explained answer · compare your reasoning

Without a bind mount, it reads the image copy. Rebuilding incorporates the edit. Runtime environment variables can vary without rebuilding because os.environ is read when Python runs.

Independent variation: add a second environment-selected word to this tiny example. Predict the default and explicit-value outputs, run both, then explain why this differs from editing source. Keep the assessed project untouched until the next lesson.
