# Flexible sequence
Each numbered HTML lesson has one outcome and a natural pause; split a lesson further whenever prediction becomes guessing. There is no daily hour quota.

1. L1: baseline probes and only the prerequisite bridges actually needed.
2. L2: environment and supplied fixture checks; explain the enqueue boundary.
3. L3–4: tiny image, then learner Dockerfile. Import-only check can work before app hooks.
4. L5–6: addresses, compose topology, startup gates and named volumes. Defer full startup until hooks exist.
5. L7–9: readiness policy → JSON event → request middleware, each with focused tests.
6. L10: complete the deferred startup; job smoke, vector probe, dependency failure and persistence observation.
7. L11: all local tests/lint, then learner CI draft and failure-to-pass evidence.
8. L12: runbook, diagram, scoped Git review and later committed fresh-copy trial.
9. L13: code reading, independent explain-back and variation, then retrieval after about two days and one week.

Use weekly-logs/week-07.md for actual attempts, plan/progress.md for evidence-backed state, projects/local-stack/decisions.md for operational choices. Author verification never ticks progress.
