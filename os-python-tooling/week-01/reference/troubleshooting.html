Week 01 / Foundation

Debug with evidence.

First write: command, working directory, expected result, actual result. Reproduce with the smallest input. Read a traceback’s final exception, then trace upward to your code.

No such file or directory

Inspect: Run pwd and ls. Check case and whether your path starts with /. A relative path is resolved from your working directory.

Next step: Change to the stated lesson directory or correct the path; do not move files blindly.

command not found

Inspect: Use command -v python, uv, git, or rg. Open a new shell after installing a tool.

Next step: This machine already has Python/uv/Git. If a tool is missing elsewhere, use its official installation instructions for that machine.

Permission denied

Inspect: Inspect ls -l for the file and parent directories. Check whether you are reading a file or directly executing it.

Next step: Work in your own practice directory; do not apply sudo or chmod 777 indiscriminately.

uv cannot download dependencies

Inspect: Separate network failure from a Python failure. Read the package/index URL and error.

Next step: Retry with connectivity. Use the same project directory; do not install tools into system Python as a workaround.

ModuleNotFoundError: week1_toolbox

Inspect: Check pwd, uv sync, and the interpreter path.

Next step: Run uv run from the toolbox; do not fix a src-layout setup issue by randomly moving modules.

NotImplementedError

Inspect: The starter deliberately leaves core functions unfinished.

Next step: Follow lessons 12–14 and implement the named function. This is expected before your attempt.

AssertionError

Inspect: Compare actual and expected values in the failing test. Identify one violated contract.

Next step: Run only that test with uv run pytest path/to/test.py -k name -vv, repair your function, rerun the focused check.

JSONDecodeError

Inspect: The file was read, but the text was not valid JSON. Inspect the indicated line/column.

Next step: Use double-quoted keys and valid values; remove trailing commas. Test invalid inputs intentionally too.

TypeError

Inspect: Inspect type(...) for the values at the failing operation.

Next step: Choose explicit conversion or a different operation; explain why the types should change.

Git identity unknown

Inspect: Git needs an author for commits.

Next step: Set your own repository-local user.name and user.email, then retry the commit.

Git tracks the wrong repository

Inspect: Run git rev-parse --show-toplevel before staging.

Next step: Initialize the toolbox locally as described in lesson 05. Do not stage unrelated parent notes.

Push rejected / pull cannot fast-forward

Inspect: Fetch and inspect git log --graph --oneline --all.

Next step: Two lines of work may diverge. Ask your teacher to walk through integration; avoid force-push.

Browser quiz does not respond

Inspect: Check whether JavaScript is disabled.

Next step: Use the expected-result disclosure and explain-back prompts; lessons remain readable offline.
