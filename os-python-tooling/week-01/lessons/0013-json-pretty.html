Week 01 / Foundation

Build a JSON pretty-printer

Format JSON without changing its meaning or source file.

Two short passes: explanation, then practice · pause between them; project labs may take longer

Worked explanationPracticeRecall and transfer

The idea

Implement pretty_json(text) in json_pretty.py. Contract: parse a JSON string, then return text with two-space indentation and sorted object keys. Support any valid JSON value, including lists and scalars. Do not print inside the function. Invalid JSON must raise JSONDecodeError. Use the standard library, not a hand-written parser.

The wrapper reads a file in UTF-8 and prints the formatted result. Standard output is the useful result; standard error is the diagnostic channel. The source file is never rewritten by the command. Shell redirection can still destroy it if you redirect output onto the input path.

Build the mental model

Understand formatting versus meaning

These two strings encode the same JSON object: {"a":1,"b":2} and { "b": 2, "a": 1 }. Their whitespace and key order differ, but parsing produces equal dictionaries. A formatter may change presentation while preserving that value. The project also specifies a particular presentation—two spaces and sorted keys—so some tests check exact text and others check parsed meaning.

import json

value = {"ready": True, "reason": None}
text = json.dumps(value)
print(type(text).__name__)
print(json.loads(text) == value)

The outputs are str and True. The JSON text uses lowercase true/null, but you supply Python objects with True/None to dumps. Do not build JSON by replacing quote characters in str(value): nested quotes, escaping and booleans make that approach fragile. The standard library owns syntax; your function owns the chosen formatting options.

Follow the two failure paths

A newline printed by the CLI is separate from the string returned by pretty_json. The function should return just the formatted text specified in its contract; print adds its usual terminating newline. Tests can call the function without launching a terminal, which makes a failure easier to isolate.

Make two observations before writing the function

In an interpreter, serialize {"z": 1, "a": 2} once with indentation and once with sorted keys. Observe which part of the output changes for each option. Then combine the options yourself. When you see the formatting behavior clearly, implement the function from its two conceptual steps.

Misconception check

“Valid JSON must be a dictionary.” False: an array, number, string, boolean or null is valid JSON too. This is why your test inputs include 42 and [1, true, null]. An API may impose a narrower shape, but this utility does not.

Hint ladder

1. Translate text to a Python value. 2. Translate that value back to text. 3. Look up indent and sort_keys in json.dumps. 4. Let the parsing exception reach the command wrapper.

Expected result · open after your attempt

Keys are sorted and nested content is indented. true and null are JSON spellings, unlike Python True and None. Malformed input exits 2 with a diagnostic. Formatting need not preserve original whitespace; parsing the output must preserve the represented value.
