Build a precise log filter

The idea

Implement filter_lines(lines, level) in log_filter.py. Our tiny log format is LEVEL message. Only INFO, WARNING, ERROR are valid requested levels. Match the first whitespace-delimited token exactly and case-sensitively. Ignore blank lines and preserve each matching input line unchanged, including its newline. Invalid requested level → ValueError. This is a teaching format, not a universal log parser.

Build the mental model

Separate the selection key from the original line

line = "  WARNING   retry later\n"
parts = line.split(maxsplit=1)
print(parts)
print(repr(line))

The split result is ["WARNING", "retry later\n"]. Leading whitespace is skipped by this whitespace split. The original line still retains its leading spaces, internal spacing and newline. repr shows an unambiguous representation including escape sequences. If you reconstruct a line from split pieces, you can accidentally change its formatting. Use the pieces to decide whether to keep the original.

Trace the decision on different inputs

Original lineTokens after split(maxsplit=1)Keep for ERROR?
ERROR first\n["ERROR", "first\n"]Yes
INFO ERROR recovered\n["INFO", "ERROR recovered\n"]No
ERRORISH almost\n["ERRORISH", "almost\n"]No
blank whitespace[]No; avoid indexing an empty list
ERROR["ERROR"]Yes; message is not required by this contract

Case sensitivity is intentional: ERROR and error are different tokens. If you want case-insensitive behavior later, change the contract and tests first rather than quietly changing it while implementing this version. The requested level also has a contract: DEBUG raises ValueError even when the input list is empty.

A smaller selection exercise

Given ["keep", "skip", "keep"], build a new list containing only entries equal to "keep". Use an explicit loop and if. Do not modify the list you are iterating over. This simple exercise isolates selection from parsing. Once you can explain it, add the token extraction step for real lines.

The provided wrapper uses splitlines(keepends=True), so each line retains its line ending. writelines writes each selected string as-is and does not add separators. Returning unchanged lines prevents lost newlines or doubled newlines. This is an example of a small output requirement that a happy-path printout can easily hide.

When a test fails

Extra INFO lines suggest substring matching. IndexError on blanks suggests indexing before checking for tokens. An extra blank line between results suggests adding a newline to a line that already has one. Find the smallest input that exposes the issue.

Hint ladder

1. Validate the requested level using membership. 2. Start an output list. 3. Split each line into at most two pieces; a blank line gives no tokens. 4. Compare token zero to level, then append the original line. 5. Return the list after iteration.

Expected result · open after your attempt

The sample has two ERROR lines. INFO with ERROR in its message must not match. Unknown requested levels produce command exit status 2. An empty result is successful and prints nothing. The tests distinguish token matching from substring matching.
