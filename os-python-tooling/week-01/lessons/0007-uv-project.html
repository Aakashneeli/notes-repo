The idea

A Python interpreter executes your code. uv manages project environments and dependencies. In a project, uv run prepares/synchronizes the environment as needed, then starts the command there. pyproject.toml declares requirements and project metadata; uv.lock records resolved versions; .venv contains the environment. Commit the first two, ignore the third.

Your starter has an explicit build system so its src/week1_toolbox package can be installed. The script mapping file-counter = "week1_toolbox.file_counter:main" connects a shell command to a Python function. A dev dependency group holds tools such as pytest; they are not runtime requirements of your three standard-library utilities.

Read the primary source: uv: working on projects · uv: dependency groups · uv: packaging and command entry points

Build the mental model

Trace one invocation

shell reads: uv run file-counter data/count
  → finds uv using PATH
  → uv discovers the Python project
  → prepares the project environment as needed
  → invokes the installed file-counter entry point
  → Python calls week1_toolbox.file_counter.main
  → main reads data/count and calls your function
  → result or error returns to the shell

Being in the intended project matters. From the course root, a relative script path can exist but the nearest project environment may not be the toolbox environment. Follow the lesson’s starting-directory instruction. uv run uses the project context; it is not merely a spelling variation for any Python on your machine.

Read the configuration, one table at a time

Section or keyPurpose in this toolbox
[project]Name, version, supported Python and runtime dependencies
dependencies = []No third-party library is needed by these tools at runtime
[dependency-groups] / devpytest supports development, not normal command execution
[project.scripts]Maps user-facing command names to module:function entry points
[build-system]Tells tooling how to build/install this src-layout package

json and pathlib come with Python’s standard library, so importing them does not mean adding packages with those names. pytest is a separate dependency. A distribution name can contain a hyphen (week1-toolbox) while the import package uses an underscore (week1_toolbox). The console command can have its own readable name.

Why repeatability needs more than “it runs here”

A lockfile fixes the resolved dependency set, but a second machine still needs a compatible Python version and access to packages that are not cached. uv sync --locked checks that the lockfile agrees with the manifest rather than silently updating it. If you intentionally change dependencies, use uv to update the manifest/lockfile, review both and commit them together. Do not hand-edit installed files under .venv; they are reproducible output.

Mini-check: missing import versus missing data

ModuleNotFoundError asks whether the interpreter can import a module. FileNotFoundError asks whether a filesystem operation found its input. Installing another dependency cannot repair a misspelled data/example.json path. Inspect the exception before choosing a fix.

Expected result · open after your attempt

The interpreter path should point inside the toolbox .venv, and the imported module should point into its src directory. --help should work even while exercise functions are unfinished. uv run pytest will initially FAIL with NotImplementedError; that is the exercise starting line, not an installation failure.
