The idea

A green check proves the tested behavior, not complete understanding or every possible edge case. This week ends when you can reproduce the tools, explain their boundaries, make a change, and debug a failure. Your log records evidence; the teacher writes learning records only after reviewing demonstrated understanding.

Read the primary source: pytest: first tests · Pro Git: recording changes · uv: working on projects

Build the mental model

What a good explain-back sounds like

Weak: “uv runs my Python and Git saves it.” Stronger: “From the toolbox directory, uv reads the project configuration and ensures the project environment is ready. The console entry point calls main. argparse converts the folder argument to a Path. My function validates it, examines direct entries and returns an integer. main prints it or translates an expected filesystem error to stderr and exit 2.” Use this as an example of specificity, then explain a different command in your own words.

Do not attempt all variations at once. Pick one, predict, test, and explain. If you require the example to answer, mark that topic “with hints” and revisit it. This is useful diagnosis, not failure. The workshop offers smaller repair tasks when a full tool still feels too large.

A practical debugging report

Record the exact command and working directory; paste the smallest relevant input; state expected and actual output; identify the failing function or test; explain the assumption that was wrong; record the change and rerun result. “Fixed a bug with AI” is too vague to guide future practice. “I returned inside the loop, so only one entry was processed” gives you a concrete pattern to notice next time.

Recover independently from a blocked session

If setup is blocked, isolate whether the command exists, the project is found, packages can be downloaded, or an import fails. If Python is blocked, inspect one value’s type and the next line that will execute. If Git is blocked, inspect status and history before changing them. When you ask your teacher for help, bring this evidence and request one hint. You do not need to struggle indefinitely, but you do need to keep the reasoning visible.

End-of-week reflection

Write three things you can now do with a blank editor, two concepts that still need hints, and one task to repeat next week. Do not convert elapsed study time into a mastery claim. Link your actual code and observations to the weekly log.
