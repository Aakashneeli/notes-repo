The idea

A list is an ordered, mutable sequence; a dict maps keys to values; a set stores unique elements without a positional ordering contract. Use a list for file entries, a dict for named record fields, and a set for unique log levels. These are everyday Python tools in this course; there are no algorithm challenges.

Assignment does not automatically copy a list. Two names can refer to the same mutable object. append changes a list and returns None. Membership in a dict checks keys. get provides a fallback for a missing key, while indexing a missing key raises KeyError.

Build the mental model

Trace aliasing before you try to fix it

first = ["a.txt"]
second = first
second.append("b.txt")
third = first.copy()
third.append("c.txt")
NamesObject contents at the endRelationship
first and second["a.txt", "b.txt"]Two names refer to the same list
third["a.txt", "b.txt", "c.txt"]A separate outer list

Rebinding and mutation differ. second = [] points second at a new list; it does not empty first. second.append(...) modifies the existing shared list. For this list of strings a shallow copy is sufficient; do not assume it recursively clones nested dictionaries or lists.

Make the most common updates

files = []
files.append("a.txt")
files.append("b.txt")
files[0] = "renamed.txt"

record = {"name": "a.txt", "processed": False}
record["processed"] = True
record["size"] = 12

levels = set()
levels.add("INFO")
levels.add("INFO")

The final files list has renamed.txt and b.txt. The dictionary has three keys; updating processed replaced its associated value. The set has one element because adding the same value twice does not create a duplicate. Empty {} makes a dict, so use set() for an empty set. Do not rely on the order in which a set prints.

To read every field, use for key, value in record.items():; each iteration provides a key/value pair. Two loop names unpack that pair. A plain for key in record: visits keys. These operations let you work with real records without learning an algorithm pattern.

A common bug you should recognize

files = ["a.txt"]
files = files.append("b.txt")
print(files)

The print shows None. append updated the original list and returned None, which you then assigned to files. The repair is two separate intentions: call files.append("b.txt") to mutate, then inspect files. Do not assign the result of an in-place method unless its documented return value is what you want.

Mini-check

For {"level": "ERROR"}, "level" in record is True and "ERROR" in record is False. record.get("missing", "fallback") returns fallback; record["missing"] raises KeyError. Choose whether absence is normal or an error.
