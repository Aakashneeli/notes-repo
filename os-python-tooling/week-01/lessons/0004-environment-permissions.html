Week 01 / Foundation

Understand a program’s surroundings

Pass a setting to Python and inspect a file’s permissions.

Two short passes: explanation, then practice · pause between them; project labs may take longer

Worked explanationPracticeRecall and transfer

The idea

A process is a running program. A shell starts child processes. Exported variables are inherited by subsequently started children; a child cannot change its parent’s environment. PATH tells the shell where to search for executable commands. An environment variable is configuration, not encrypted storage. A .env file is ordinary text and is not automatically loaded by Python.

In ls -l, the first character identifies the file kind; the next nine positions describe read, write, execute for owner, group, others. Directory execute permission means traversal. Read permission and executable permission differ: python file.py needs to read the file, whereas directly executing ./file.py also needs executable permission and an interpreter directive.

Read the primary source: GNU Bash manual · GNU Coreutils manual

Build the mental model

Trace one setting through a process boundary

shell: COURSE_MODE=practice
  └── starts Python with an inherited environment
        └── Python reads COURSE_MODE and prints practice

Without export, a normal shell variable is available to that shell but is not newly added to the environment of child commands. export marks it for inheritance. For one invocation only, use COURSE_MODE=demo python -c 'import os; print(os.environ["COURSE_MODE"])'. That assignment configures that invocation; it does not permanently edit your shell startup files.

All environment values arrive as strings. A value such as "2" needs conversion before arithmetic. A missing variable and an empty variable are different: missing means no entry exists; empty means an entry has value "". os.environ.get("NAME", "fallback") uses the fallback only when the entry is missing.

Decode a permission string

-rw-r-----
│└─┬┘└─┬┘└─┬┘
│ owner group others
regular file

The owner has read/write; members of the owning group have read; others have no permissions from these mode bits. x on a directory allows traversing it. Reading a file may require traversal permission on its parent directories too. Mode bits are an introductory model; ACLs and privileged users can add further rules. That is why we inspect rather than guessing from an error message.

Changing a mode is different from changing ownership. chmod changes mode bits; it does not make a file yours. A permission error can also involve the destination directory where you are trying to write. Identify the operation and exact path before deciding what permission is missing.

Predict before trying

Start Python from your shell, change COURSE_MODE using os.environ inside Python, then exit. Will the shell now have the changed value? No: the child changed its own environment, not its parent’s. Try this with a dummy value and inspect only that variable.

Try it yourself

cd /home/an10/code/notes-repo/os-python-tooling/week-01
command -v python
command -v uv
export COURSE_MODE=practice
python -c 'import os; print(os.environ.get("COURSE_MODE", "unset"))'
unset COURSE_MODE
python -c 'import os; print(os.environ.get("COURSE_MODE", "unset"))'
printf 'dummy only\n' > practice/permission-demo.txt
chmod u=rw,go= practice/permission-demo.txt
ls -l practice/permission-demo.txt

Use dummy values only. Do not dump all environment variables into notes. Read help export and chmod --help to check the command syntax.

Expected result · open after your attempt

Python prints practice, then unset. The demo permissions should start -rw-------. The owner can read/write; no execute bit is set. Do not use chmod 777 or sudo as a reflex when a tool fails—first inspect the path and ownership.
