A worked reading note

Question: “Does split(" ") behave like split() when a log line contains extra whitespace?” Open the official string-method documentation linked below and locate str.split. Notice what the default separator means. Now close the page and predict:

line = "  ERROR   disk full  "
print(line.split())
print(line.split(" "))

Start python from the course root and execute the snippet. The first output is ['ERROR', 'disk', 'full']. The second is ['', '', 'ERROR', '', '', 'disk', 'full', '', '']. Default splitting treats runs of whitespace as separators and drops surrounding empty pieces. A literal space separator splits each space separately. This matters because the log filter must identify a level even after indentation.

Your note and variation

Fill one entry in the reading log with the exact docs section, your prediction, actual output and your explanation. Then try a tab between INFO and ready. Do not copy the paragraph above into your notes.

Hint 1

A tab is whitespace, but it is not the same character as an ordinary space.

Hint 2

Compare "INFO\tready".split() and .split(" ").

Explained answer · after your attempt
assert "INFO	ready".split() == ["INFO", "ready"]
assert "INFO	ready".split(" ") == ["INFO	ready"]

Both assertions pass. The explicit separator finds no ordinary spaces, so it retains the tab inside one string. Your note should connect this observation to the intended log format.
