Week 02 / Foundation

Debug a value before changing the code

Read one step, try it, then pause. These are completed teaching examples; proposed repairs and variations are learner exercises.

Your tools will receive text from files and the terminal. A useful first debugging question is “What value and type reached this operation?” A traceback identifies the failing operation; it does not decide what your program intended.

A completed failure trace

Start in the course root, run python, then type the following Python statements. Leave the REPL using exit() when finished.

retries = "2"
print(type(retries).__name__)
print(retries + 1)

The first assignment creates a string. The first print shows str. The next expression attempts to concatenate text with an integer and raises TypeError before print receives a result. Nothing has incremented retries. To do arithmetic, int(retries) + 1 produces 3. To display a label, f"retry {retries}" produces text. The purpose determines the repair.

A silent failure can be just as important

names = ["one"]
result = names.append("two")
print(names)
print(result)

The outputs are ['one', 'two'] and None. The call mutates the list and returns None. If you wrote names = names.append("two"), you would rebind names to None and lose that name's access to the list. Read the documented return value before assigning a method call.

Your repair

Without copying a project function, write a snippet that starts with sizes = ["12", "8"] and prints 20 as a number. Then add a third value and predict the result. Keep the input list unchanged.

Hint 1

Inspect each element type, not only the container type.

Hint 2

Initialize a total before the loop. Convert each size with int before adding.

Explained answer · after your attempt
sizes = ["12", "8"]
total = 0
for size in sizes:
    total += int(size)
print(total)
assert total == 20
assert sizes == ["12", "8"]

The running total is 0 → 12 → 20. Conversion creates integers without changing list entries. Adding "5" would produce 25. The checks make both the numerical result and preserved input observable.

Recall and transfer

Explain why converting the entire list with int fails. Predict what changes if an element is "many". It should raise ValueError during conversion; do not hide it with a fake zero. Record your own wrong assumption, if any, in the mistake log.
