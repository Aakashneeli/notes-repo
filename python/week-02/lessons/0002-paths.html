The idea

A terminal is the window; a shell reads your commands; the operating system runs programs and manages files and processes. Your shell has a current working directory. A path beginning with / starts at the filesystem root. Other paths start from the working directory. . means here; .. means parent; the shell expands ~ to your home directory.

A directory contains named entries; a regular file stores data. Quotes keep a path with spaces as one argument. Linux names are case-sensitive. WSL offers a Linux environment on Windows, but this machine is already Linux: use the commands directly.

Read the primary source: GNU Bash manual · GNU Coreutils manual

Build the mental model

Read a path as directions

python/week-02/         ← course root
├── README.md
└── projects/
    └── week-02-toolbox/  ← toolbox root
        └── data/
            └── example.json
Starting directoryPath to readWhy
Course rootprojects/week-02-toolbox/data/example.jsonGo down through projects, toolbox, data
Toolbox rootdata/example.jsonYou are already inside the toolbox
Toolbox data/example.jsonThe file is directly here
Toolbox data/../../../README.mdGo up to toolbox, projects, course; read course README

Read the last row carefully: it intentionally points to a different file. Each .. goes up one level. A path is a location description, not a command to move there. cat reads at that location; cd changes the shell’s location. A filename extension such as .json suggests a format, but does not guarantee the contents are valid.

Read the command as separate pieces

cat "practice/terminal/my note.txt"

cat is the command name. Everything inside the quotes becomes one argument. Without quotes, the shell splits at spaces and cat tries to read more than one file. Options commonly begin with -: in ls -la, -l requests detail and -a includes names beginning with a dot. The quotes are shell syntax and are not part of the filename.

Make, copy and rename a disposable file

After the main exercise creates practice/terminal/my note.txt, run these from the course root:

cp "practice/terminal/my note.txt" practice/terminal/copy.txt
mv practice/terminal/copy.txt practice/terminal/renamed.txt
ls -l practice/terminal
cat practice/terminal/renamed.txt

cp leaves the original and makes a copy. mv moves or renames an entry; after the rename there is no copy.txt. Both can overwrite a destination, so inspect names first and use this disposable directory. To delete only the duplicate, use rm -i practice/terminal/renamed.txt and read its confirmation. Deletion is not the same as moving a file to a graphical trash folder.

Expected result · open after your attempt

The corrected relative path is projects/week-02-toolbox/data/example.json. The two earlier cat commands read the same file. Changing your working directory changed how the relative path was interpreted; it did not move the file.
