Week 02 / Foundation

Follow the return all the way back

Read one step, try it, then pause. These are completed teaching examples; proposed repairs and variations are learner exercises.

A function's result belongs to its caller. Printing is a side effect; return hands back a value and ends the call. Understanding that difference lets your tools be tested without reading a screen.

Trace the bug

Start in the course root. Create practice/control-attempt.py in your editor, save this deliberately broken teaching example, and run python practice/control-attempt.py.

def total(sizes):
    answer = 0
    for size in sizes:
        answer += size
        return answer

print(total([3, 4]))
print(total([]))

First call: answer starts at 0; size becomes 3; answer becomes 3; return immediately ends the function. The value 4 is never visited. First output: 3. In the empty call, the loop body never executes and the function falls off the end, returning None. Second output: None. This is legal Python with wrong behavior.

Your repair and checks

Repair the placement of return so the function gives 7 for [3, 4] and 0 for []. Then run these checks below your function:

assert total([3, 4]) == 7
assert total([]) == 0
assert total([5]) == 5
print("three cases passed")
Hint 1

Which line must run after every item has been visited?

Hint 2

Dedent return so it lines up with for, still inside def.

Explained answer · after your attempt
def total(sizes):
    answer = 0
    for size in sizes:
        answer += size
    return answer

The trace is now 0 → 3 → 7, followed by return. For [], answer stays 0 and the return still executes. The three checks print only “three cases passed” when successful. An assertion failure points to the first mismatch.

Do not confuse three ways to leave

continue skips the rest of the current iteration. break exits the loop and permits later function statements. return exits the function. They are not interchangeable fixes for an early exit.

If total only printed answer, a caller doing result = total([3, 4]) would receive None. Keep the core's calculation and the caller's presentation separate, as in the three-tool wrappers.

Recall and transfer

Close the repair. Recreate it and trace [0, 2, 0]. Then explain why initializing answer inside the loop loses earlier work. Write a check for that bug before trying the deliberate breakage.
