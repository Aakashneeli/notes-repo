The idea

A module is an importable unit, often a .py file. A regular package is a directory of modules with an __init__.py. The path src/week2_toolbox/json_pretty.py names a file; week2_toolbox.json_pretty is an import path. Installing the package makes the src layout importable. A relative data path still depends on the working directory, not on the module’s location.

Use Path for filesystem operations. read_text(encoding="utf-8") returns text. json.loads parses text into Python values; json.dumps serializes values into text. Reading, parsing, formatting, and writing are separate steps with separate possible failures.

Build the mental model

Observe the type at each boundary

from pathlib import Path
import json

source = Path("data/example.json")
text = source.read_text(encoding="utf-8")
record = json.loads(text)
service = record["service"]
NameTypeMeaning
sourcePathA description of where to read; creating it has not opened the file
textstrCharacters decoded from the file bytes
recorddict for this inputParsed JSON object; other JSON inputs can produce a list or scalar
servicestrThe value stored under the service key

encoding="utf-8" selects how bytes become characters. You do not need to memorize encoding internals this week; you do need to distinguish a read/decoding failure from a JSON syntax failure. JSON’s true, false and null become Python’s True, False and None. A Python dict’s printed representation is not necessarily valid JSON, so use json.dumps to serialize it.

Separate missing data, invalid data and wrong shape

A file can exist, be readable, contain valid JSON, and still not have the structure your program expects. For [], parsing succeeds but indexing it with "service" is wrong for a list. For {}, parsing succeeds but the key is missing. The pretty-printer contract accepts these inputs because it only formats values; a service-config reader would need a different validation contract.

Read a traceback as a path to a failure

def read_port(text):
    return int(text)

print(read_port("many"))

The last traceback line identifies ValueError: the string cannot be interpreted as an integer. Look upward for the line inside read_port, then the call that supplied "many". Fix the input or explicitly handle this expected invalid-input case. Do not catch every exception and return an empty result; that hides programming errors and makes failures look like success.

try:
    port = int("many")
except ValueError:
    print("Port must be an integer")

try runs the normal path. A matching except handles the named failure. raise ValueError("explanation") deliberately signals invalid input; it is different from printing an error and carrying on. In the exercises, core functions raise expected exceptions and wrappers translate them to command diagnostics. Type hints such as text: str and -> str document intent; Python does not automatically validate them at runtime.
