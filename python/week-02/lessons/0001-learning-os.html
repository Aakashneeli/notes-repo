The idea

“Learning OS” here means your learning operating system: a repeatable way to study. Linux is one tool inside it. The roadmap targets AI backend engineering; its baseline says you have seen Python and Git but want stronger ownership. We will start there and adjust after your first explain-back.

Use this loop: predict → attempt → observe → explain → change one thing → retry tomorrow. Reading an answer feels easier than recalling it; our completion rule requires a fresh attempt. A lesson gives you an idea, its lab gives you evidence, and a learning record is written only after you demonstrate understanding.

Build the mental model

First, know where to type

You will use three places: the browser for reading, a text editor for writing files, and a terminal for running commands. Opening a .py file in the editor does not execute it. Saving the file makes your edits available to the next run. Use the editor you already know; this week does not require learning a new editor.

Where you areWhat belongs thereHow to recognize it
Shellpwd, cd, git, uv, pythonYour normal terminal prompt, often ending in $
Python interpreterprint(2 + 3), assignments, function callsThe >>> prompt; ... requests continuation
A .py filePython statements, with no >>> promptsThe editor shows a file such as hello.py

The prompt itself is not part of the command. If a guide shows $ python, type python. At >>>, type Python code. To get back to shell commands, use exit(). In interactive Python, finish an indented function with a blank line. In a script, indentation still matters but you do not type prompts.

A complete first run

In your editor, create practice/hello.py inside this course and save the following two lines:

topic = "backend"
print(f"I am learning {topic}")

From the course root, run python practice/hello.py. Expect I am learning backend. Change the string to Python, save, and rerun. If output did not change, check whether you saved the correct file. A script containing only 2 + 3 has no printed output; use print(2 + 3). The interactive interpreter displays expression results for convenience.

How to use explanations without fooling yourself

For every worked example, cover the output first. Write what you expect. After running it, explain one line aloud and change one input. When a task is too hard, shrink it: before writing a file counter, inspect one Path and one boolean. When a task is easy, remove the example and recreate it. Your next task should test a small uncertainty you can name.
