Find which boundary failed

Read one step, try it, then pause. These are completed teaching examples; proposed repairs and variations are learner exercises.

Before fixing a file-based tool, identify whether it failed to locate data, decode bytes, parse text, or use the resulting object. These steps are separate; success at one does not imply success at the next.

A worked diagnosis

Starting directory: projects/week-02-toolbox inside this workspace. Start uv run python and type:

from pathlib import Path
import json
path = Path("data/invalid.json")
text = path.read_text(encoding="utf-8")
value = json.loads(text)

Creating path performs no read. read_text succeeds because the fixture exists and can be decoded. loads raises JSONDecodeError because its contents are invalid JSON. The exception includes a position; inspect the surrounding text. Installing a package or changing permissions would not repair this syntax.

Now change the path to data/does-not-exist.json and repeat the read. FileNotFoundError occurs before parsing. A Python variable from a previous REPL run can still hold an old value after a failed assignment; do not accidentally parse stale text. Re-enter the steps carefully or restart the interpreter.

Your small guard

Write token_or_empty(line): return the first whitespace-separated token or "" when there are no tokens. Try " INFO ready", "INFO", and " ". This prepares the log filter's empty-input decision without implementing the full project.

Hint 1

Predict the list returned by a whitespace-only string’s split method.

Hint 2

Test whether the list is empty before indexing it.

Explained answer · after your attempt
def token_or_empty(line):
    parts = line.split()
    if not parts:
        return ""
    return parts[0]

assert token_or_empty("  INFO ready") == "INFO"
assert token_or_empty("INFO") == "INFO"
assert token_or_empty("  ") == ""

split collapses whitespace runs into separators. Whitespace-only input produces [], which has no index zero. The guard returns before indexing. No output from these assertions means all three comparisons passed.

Common mistaken fixes

json.loads("data/example.json") parses that literal text, not a file. except Exception: return {} hides unrelated bugs and makes a broken input look like an empty object. A function should raise the expected error; the wrapper decides how to communicate it to a user.

Recall and variation

Explain the difference between missing input and valid JSON with the wrong shape. Predict json.loads("[]")["service"]: parsing succeeds, then string indexing on a list raises TypeError. A formatter accepts that array; a config reader requiring a service field needs a different contract.
