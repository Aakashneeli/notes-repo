Week 03 · Pro Python · Lesson 07

Make events useful without exposing text

Trace logger → handler → formatter → stderr, then implement safe structured events.

Four responsibilities

A logger receives an event and level. Its level filters events; a handler sends accepted records to a destination; a formatter determines their representation. DEBUG is diagnostic detail; INFO records normal milestones; WARNING flags recoverable unusual conditions; ERROR records a failed operation; CRITICAL signals severe failure. A threshold of INFO suppresses DEBUG, not WARNING.

Review EventFormatter in ../../practice/examples.py. It creates a dictionary containing only level and event, then json.dumps escapes it into valid JSON. This is structured logging: tools can parse fields without guessing where words begin. Do not construct JSON with string concatenation; quotes and newlines can corrupt the record.

A deliberately small event

import logging

record.secret = "dummy-private"

PYCODE
cd projects/text-workbench

Expected JSON: {"level":"INFO","event":"processed"}. The final cd returns you to the project for implementation. The formatted output should still contain only level and event. This demonstrates an allowlist; it is not automatic redaction if you place a secret inside the event message itself. Write the predicted keys and result in your weekly log.

Hint and feedback

Use a fixed event name such as processed. Store safe counts as separate fields. If you serialize record.__dict__, the dummy secret leaks. If you call logger.info(text), even a two-field formatter leaks text through event.

Implement the logging adapter

Edit src/text_workbench/logging_setup.py. Your JsonFormatter emits level and event, plus characters/words when present. The setup function manages only the text_workbench logger, replaces its handlers to avoid duplicate output, attaches a StreamHandler (stderr by default), applies your formatter and chosen level, and sets propagate=False so a root logger does not print the same event again. Configure once in the CLI; library imports must not configure the user's whole process.
