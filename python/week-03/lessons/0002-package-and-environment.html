Week 03 · Pro Python · Lesson 02

Make imports predictable

Run an installed src-layout package and distinguish a file path from an import path.

Follow one command

A module is a Python file. A package groups importable modules. Our distribution is named week03-text-workbench, but Python imports text_workbench; hyphens cannot be ordinary import identifiers. The src/ directory separates importable code from tests and README files. Installing the project makes that package available to the environment.

From this week's root, read projects/text-workbench/README.md as the project contract. Then enter it and inspect the supplied pyproject.toml:

cd /home/an10/code/notes-repo/python/week-03/projects/text-workbench
cat pyproject.toml
UV_CACHE_DIR=/tmp/week03-uv-cache uv sync --locked
uv run python -c 'import text_workbench; print(text_workbench.__file__)'
uv run text-workbench --help

The import path must end in src/text_workbench/__init__.py. Help shows one positional path argument without calling unfinished functions. A missing module means check pwd, uv sync and uv run python -c 'import sys; print(sys.executable)' before changing import statements.

What each configuration section does

[build-system] names Hatchling, which installs/builds the package. [project] declares metadata, Python ≥3.12 and Pydantic v2. [project.scripts] maps the terminal command to text_workbench.cli:main: import the module and call its function. [dependency-groups] separates pytest/Ruff development tools from runtime Pydantic. The Hatch wheel setting identifies the src package. Pytest discovers tests under tests; Ruff checks syntax, imports and selected errors. Ruff is not a type checker.

uv.lock records resolved versions and hashes. Leave it unchanged unless intentionally updating dependencies with uv. The generated .venv/ holds the interpreter, installed package links and dependencies. __pycache__/, pytest/Ruff caches and uv's download cache are generated infrastructure; do not inspect every file. the weekly .gitignore excludes those plus private .env and output directories. Read it once; do not commit caches.

Public versus internal

Read src/text_workbench/__init__.py. It is intentionally minimal and performs no I/O. A public function has a documented contract callers can rely on; an internal helper such as _clean_field is a naming convention, not an access restriction. Avoid circular imports: if core imports service and service imports core, initialization becomes order-dependent. Keep the core independent.

Write the observed import path and explain the distribution/import distinction in the weekly log. Variation: from the week root run projects/text-workbench/.venv/bin/python -c 'import text_workbench; print(text_workbench.__file__)'. It should still find the installed src package. No credentials, paid service or special hardware are needed.
