See where a task yields

Observe cooperative waiting and distinguish it from blocking the event loop.

Async is about waiting

I/O-bound work spends substantial time waiting for things outside the CPU, such as a network response. An event loop can run another ready task when the current coroutine yields. Writing async def creates a coroutine function; calling it creates a coroutine object, which still must be awaited or scheduled. await is a suspension point only when the awaited operation actually needs to yield.

Read ../../practice/async_demo.py, a completed experiment. asyncio.run starts an event loop for main. gather schedules two tasks. asyncio.sleep simulates asynchronous waiting without networking; time.sleep blocks the thread. Both wait, but only the first gives other loop tasks a chance during that wait.

cd /home/an10/code/notes-repo/python/week-03/projects/text-workbench

uv run python ../../practice/async_demo.py --blocking

For these equal-delay tasks, expect the nonblocking run to print A start, B start, A end, B end; the blocking run prints A start, A end, B start, B end. Record the order, not a fragile timing claim. This demonstrates local scheduling only, not network throughput.

Follow the pause

A starts and reaches await sleep; the loop can start B before A resumes. In blocking mode A's time.sleep prevents B from starting on that loop thread. Prefixing a blocking function with async def does not change what its internal operations do. CPU-heavy text transformation also occupies the thread while it runs; async syntax does not make it parallel or inherently faster.
