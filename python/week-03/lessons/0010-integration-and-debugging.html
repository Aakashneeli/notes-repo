Prove the command boundary

Run the assembled package, check failure behavior, and distinguish test evidence from assumptions.

Read the supplied wrapper line by line

Open src/text_workbench/cli.py from the project directory. argparse turns the path argument into a Path. main reads os.environ once, loads settings, configures logs and calls the service. It catches expected operational/validation failures, prints a stable safe message to stderr and returns 2. Success prints a JSON record to stdout and returns 0. The __main__ guard turns the return value into the process exit code when run as a module. The installed script calls main similarly.

NotImplementedError is deliberately not caught: unfinished work should produce an obvious traceback. Avoid catching Exception merely to make a green-looking CLI. ValidationError is a ValueError subclass, so listing both in this small wrapper is redundant but explicit. Error text is generic by design to avoid echoing private inputs; local debugging uses focused tests.

Run the contract

Read data/normal.txt, data/empty.txt and data/unicode.txt; these supplied fixtures stay unchanged. The empty file intentionally has zero bytes. From the project directory:

cd /home/an10/code/notes-repo/python/week-03/projects/text-workbench
uv run pytest -q
uv run text-workbench data/normal.txt
uv run text-workbench data/empty.txt
uv run text-workbench data/unicode.txt
TEXT_MAX_CHARS=1 uv run text-workbench data/normal.txt
printf '%s
' "$?"
uv run ruff check .
uv run ruff format --check .

After implementation, all tests pass. Expected stdout records: normal 17 characters/3 words; empty 0/0; Unicode 7/2. Each successful run emits a separate INFO JSON log to stderr. Too-small config produces no stdout, one safe stderr message, exit 2. Shell stream interleaving does not guarantee visual ordering; tests capture streams separately. Ruff format --check reports formatting without rewriting files; use uv run ruff format . deliberately on your implementation when needed.

Make a bug teach something

Read tests/test_logging_cli.py's run_cli helper: it invokes the same environment's Python via sys.executable, strips inherited TEXT_ variables to isolate the test, captures streams and does not raise on nonzero exit. Negative tests check an absent path and invalid/too-small config. Large-file data is generated only under pytest's tmp_path; no giant fixture is committed.

Temporarily change one rule in your own implementation (for example, count raw characters), run its focused test and capture the failure. Restore the rule and show the same test passes. Add one new regression test you can justify, such as a Unicode whitespace input or a missing required output field. Never edit a supplied assertion just to accept an incorrect result.

Record the failing command, root cause, fix and regression test in python/mistake-log.md using the template. Explain what every test proves and what it does not: mocks isolate orchestration, fixtures test local files, subprocesses test CLI integration. No live service or deployment is involved.
