Choose a model at the boundary

Compare dataclasses and Pydantic by running the same kind of bad input through each.

Objects group named data

A class defines a kind of object; an instance holds one particular set of fields. A dataclass can generate initialization and a readable representation from annotated fields. It is useful for internal records whose validity is established elsewhere. Pydantic models add runtime parsing/validation and serialization, useful when config arrives as strings or outputs must obey a contract.

Read ../../practice/examples.py from the project directory. It is a completed teaching example, not your project answer. Badge("Ada", "two") retains the wrong visits type. Booking(seats="2") converts the string into integer 2. StrictBooking(seats="2") rejects it. Constraints also reject zero seats. ConfigDict(extra="forbid") catches unknown fields rather than silently ignoring typos.

Hint 1

Inherit BaseModel and attach a Field to quantity.

Explained beginner answer
from pydantic import BaseModel, Field
class Ticket(BaseModel):
    quantity: int = Field(gt=0, strict=True)

Only 1 passes among those inputs. The constraint checks positivity; strictness excludes strings and bool even though bool is a Python int subclass.
