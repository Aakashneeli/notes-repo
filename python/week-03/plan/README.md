# Flexible sequence

Use the numbered HTML lessons, pausing after each tangible win. A lesson can span more
than one sitting. Hints are progressive; close them before reproducing an answer.

1. Lesson 1: baseline checks, scope, evidence; use only needed prerequisite links.
2. Lessons 2–4: installed package, function/test bridge, typed contracts; practice lengths/label.
3. Lessons 5–6: dataclass comparison, runtime models, settings; practice Ticket/read_limit.
4. Lessons 7–8: logging and workflow boundaries; practice allowlist/describe; implement project.
5. Lesson 9: async observation and sequential variation; keep the CLI synchronous.
6. Lesson 10: integration, invalid/empty/large files, a reproduced bug and regression check.
7. Lesson 11: read real upstream code; fill architecture note and draw your actual module diagram.
8. Lesson 12: independent explanations, README, local Git review and reproducibility.
9. Roughly +2 days: closed-notes recall of types, settings and async ordering.
10. Roughly +7 days: independent changed requirement with tests and diagram update.

Interleave after initial success: revisit a config failure while testing logging, or an
import failure while reading upstream code. If support is still needed, record it and
repeat a smaller case. No time quota or author check establishes mastery.
