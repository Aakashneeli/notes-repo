Week 10 / Lesson 01

Establish what actually runs

Trace one request and separate existing evidence from assumptions.

The purpose of this week is to own the consequences of your backend design. A request can succeed while leaking data, or look fast because failed requests were omitted. We will ask what each component knows, what can fail, and what evidence would change a design decision.

The authority is the source roadmap's numbered #week-10: System Design, LLD/HLD, Observability, Performance, Reliability, and Security Review. Weeks 1–3 supply Python/tooling, 4–7 the API/data/jobs/container pieces, and 8–9 retrieval and agent workflows. Week 10 connects them; cloud deployment comes later. The short six-item sequence summary in the roadmap does not override its twelve numbered weeks.

A prerequisite bridge you can trace

caller → query() → simulated retrieval wait → simulated model wait → result dictionary

Read fixture.py. async def defines work that may pause. Calling it produces a coroutine; await runs it and waits for its result. asyncio.sleep simulates waiting without contacting a service. return gives the caller a dictionary; raising TimeoutError leaves the function early. With fail=True, generation never runs. This fixture has no HTTP/authentication, storage, semantic retrieval, tokens measured by a provider or LangGraph.

Before running anything, predict: Does a timeout return an empty answer? Does changing a tenant change this fixture? Answers: it raises an exception; there is no tenant parameter. That missing boundary must appear in your assumptions, not be mistaken for a secure implementation.
