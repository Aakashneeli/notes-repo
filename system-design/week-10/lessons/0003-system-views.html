Week 10 / Lesson 03

Draw the system at two useful zoom levels

Create context and container views without claiming unbuilt components exist.

High-level design (HLD) describes the running pieces and communication between them. A context view shows who uses the whole system and its external dependencies. A container view opens that system to show deployable applications and data stores. A C4 “container” is a running application or data store, not necessarily a Docker container.

Worked example: a small library

Reader ──searches catalogue──→ Library system Library system ──sends reminder──→ Email provider

Zoom inside the library: a web API accepts searches, a database stores titles, and a worker sends reminders. The context's one Library box becomes those internal components. An arrow labelled “HTTPS search request” says more than “uses.” Adding ten infrastructure icons without a purpose makes a diagram harder to check.

Apply the same questions to an AI backend

The client submits queries/uploads to the API. The API checks identity and authorization. Postgres can own document/job metadata; object storage holds original bytes. Redis may carry job coordination or cache values. Workers parse/chunk/embed uploads and update a vector database; a model provider produces embeddings or answers. Observability receives selected events/traces. Separate ingestion from asking: an upload becoming durable does not mean searchable chunks already exist.

This is a vocabulary for your review, not a requirement to invent extra services. Inspect the actual files linked in the project README. In architecture.md, label every component implemented, fixture, or proposed; record evidence paths. Unknowns remain unknown. Your current prerequisite fixture has only one process.

Lab: your first two diagram pages

Read the project contract. It introduces the architecture packet you will build throughout this week. Open architecture.drawio in draw.io Desktop if installed, or the web editor. Select Device storage, then File → Open From → Device. This supplied editable file contains five labelled task pages, not a finished design. No account is required for local saving. Do not publish it or connect cloud storage.

Starting from the weekly root, edit projects/architecture-review/diagrams/architecture.drawio. On Context, draw the client, whole backend, provider and telemetry destination with labelled arrows and a legend. On Containers, replace the whole-backend box with the components you actually have or propose. Include API, workers, DB, Redis, vector store, object storage, model provider and observability; mark absent ones proposed and explain why. Show public/private and external-provider boundaries. Save back to the same path; reopen to check persistence. If your browser downloads a second copy, move that deliberately to the intended path only after checking which is newer.

Editor bridge: select the Context page tab, drag a rectangle from the shapes panel onto the canvas and double-click its text to name it. Add a second rectangle, then drag a connector between their connection points; double-click the connector to label its data/action. Use a large enclosing rectangle or dashed boundary to group components, and a short legend to explain your status markings. Start with just the client and backend, save, and reopen before adding the rest. A connector merely near a shape may not remain attached when the shape moves; move one box slightly to check it.

Hint 1 — choose the zoom

If the box is “API,” you are inside the system. The context page should usually show the whole product instead.

Hint 2 — check each arrow

Read aloud “A sends B to C using D.” If you cannot fill in data and protocol, label that connection an assumption and investigate the actual entrypoint.

Evidence: link the two saved pages and explain one arrow in architecture.md. Check: every context dependency reappears consistently in the container view; no proposed cloud icon is claimed to be deployed. Variation: imagine the model provider is unavailable. Circle the affected connections without redrawing unaffected components. Continue to Lesson 4.
