Week 10 / Lesson 02

Give a module one reason to change

Inject a small interface and explain who owns policy versus storage.

Low-level design (LLD) is about responsibilities inside code. An HTTP handler translates requests and responses; a service decides the workflow; a repository hides storage operations. A service called ask should not need to know a database's connection string to decide what to do with empty retrieval.

Follow one injected dependency

class Catalog(Protocol):
    def title(self, item_id: str) -> str: ...

def label(item_id: str, catalog: Catalog) -> str:
    return catalog.title(item_id).upper()

Protocol describes the methods callers need. The colon after a parameter is a type hint, and -> str describes its result. The ellipsis describes an interface without implementing it. These hints do not validate network data at runtime. catalog is passed in by the caller: that is dependency injection. No special framework is needed.

Read examples.py. MemoryCatalog.title("book-1") looks up "Field guide"; label turns it into "FIELD GUIDE". The caller selects storage; the service selects presentation. A fake with the same method can supply a title during tests. An unknown key raises KeyError; replacing it with a blank title would hide a real failure.

Hint 1 — locate the decision

Storage gives you a title. Uppercasing belongs after that call. Return the transformed value.

Hint 2 and explained beginner answer
return catalog.title(item_id).upper()

First evaluate the method call; then call upper on the returned string. This does not uppercase the identifier.

Boundaries are a tradeoff

Too many tiny wrappers force you to chase a simple decision across files. Too few boundaries mix authentication, retrieval, provider retries and logging into one function. Prefer an interface that hides a real source of change: a retrieval port taking a trusted tenant and query, returning authorized hits. A repository must not treat a caller-supplied tenant as authenticated identity. Service rules determine what the user may do; query filters enforce the resulting scope close to the data.

Variation: sketch a search(query, tenant, limit) interface in your log. Specify returned fields and what a timeout means. Explain how a fake helps test “no hits means no model call,” and what it cannot prove about a real vector database. Add the code entrypoint, call chain and one uncertainty to the reading log.
