Week 10 / Lesson 04

Trace time, data and deployment separately

Finish sequence, data-flow and deployment views that answer different questions.

A static component picture cannot tell you whether retrieval happens before authorization. A sequence view answers in what order?; a data-flow view answers which data crosses which boundary?; a deployment view answers where does this run?. These are distinct views of the same system.

Worked trace

  1. A fictional library reader requests a private title.
  2. The API checks reader identity, then asks storage for that reader's permitted titles.
  3. Storage returns one record; the API formats a response.
  4. If storage times out, the API returns a controlled failure; it does not pretend the title is absent.

On a sequence diagram, give client/API/storage separate vertical lifelines and draw arrows top to bottom. A returned record is a reply arrow. Add an alternative failure branch after the storage call. In a data-flow view, the same action becomes labelled data moving from external input through validation to authorized data access. Order alone does not show trust.

AI-specific data flow

Document bytes enter from an uploader; parsed chunks carry source, version and tenant metadata into storage. Query text plus trusted identity selects authorized chunks. Selected text leaves your boundary when sent to an external provider. Model output comes back untrusted and must be validated before any tool execution. A telemetry export is another data exit. Vector numbers do not make the accompanying text or metadata non-sensitive.

Deployment maps processes and stores to machines/networks. A local laptop might run API and worker containers on a private Compose network; only the API port is published to loopback. Volumes persist database files separately from container lifetime. A provider is outside that laptop. Show the actual local topology separately from a future candidate; no AWS instructions are needed to draw that candidate.

Hint 1 — avoid a decorative diagram

Pick one real entrypoint and follow its calls. If no real implementation exists, title the page “Proposed target; fixture currently has only query().”

Hint 2 — test a boundary

Ask whether a retrieved instruction can cross the data-to-command boundary. Your diagram should show a validation/authorization gate between model intent and tool execution.

Variation: show where a worker restarts after writing vectors but before acknowledging its queue job. Predict the duplicate processing risk in your weekly log. Next, learn how bounded retries and idempotency address it.
