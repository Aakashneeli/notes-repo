Week 10 / Lesson 07

Read logs, metrics and traces together

Use a request ID to turn a symptom into a testable hypothesis.

A log is an event record. A metric summarizes many events over a window. A trace connects steps of one operation and their durations. When latency rises, all three answer different questions: how widespread, which requests, and which step?

Read three fictional events

Open data/events.jsonl. JSON Lines means one complete JSON object per line. The sample is supplied evidence for reading practice, not a production capture. Two requests succeed in 120 and 180 ms; one fails in 800 ms. Error rate is 1/3, not 1/2: all three attempted requests belong in the denominator. The successful-only average would hide the slow failure.

{"request_id":"demo-2","latency_ms":800,"status":"error",
 "retrieval_hits":0,"input_tokens":null,"estimated_cost_usd":null}

null means unknown here. It does not mean free. Zero hits after a timeout may mean retrieval never completed; status and stage distinguish that from a successful empty result. A request ID correlates events; it does not identify or authenticate a person. Generate one at entry, carry it through functions and job metadata, and return it in a response header. If accepting an incoming ID, validate length/characters and never treat it as authority.

Follow one slow request

Imagine a 900 ms request with retrieval 100 ms and generation 760 ms. A trace showing generation as the long child suggests provider latency; a 900 ms request with only 80 ms of measured child work suggests queueing, connection waits, missing instrumentation or event-loop blocking. Nested durations overlap: do not sum parent plus children. Backend logs also cover startup, authorization and worker failures that may sit outside AI traces.

CloudWatch mapping: write structured events to application stdout; a collector sends them to streams for running instances, grouped under shared retention/access policy. Filters can turn fields into metrics. Do not use unique request IDs as metric dimensions: that produces many distinct series. LangSmith groups model/tool/retrieval runs into traces; correlate a safe request ID but review what inputs/outputs tracing captures before enabling it. This course sends nothing.

Guided practice and immediate check

From the weekly root, implement error_rate in practice/exercises.py, then run:

python -m unittest discover -s practice -p test_exercises.py -k rate -v
Hint 1

Count statuses at least 500, then divide by all statuses. Guard empty input before dividing.

Hint 2 and explained answer
if not statuses:
    return 0.0
return sum(status >= 500 for status in statuses) / len(statuses)

The generator feeds one Boolean per status; Python sums True as 1. HTTP 400 is a client error and is outside this exercise's server-error definition. A real dashboard should also track relevant 4xx separately.

Read timed_demo in practice/examples.py: perf_counter measures elapsed time; multiplying seconds by 1000 gives milliseconds. JSON serialization provides escaping and named fields; string-concatenating raw prompts is both unreliable and unsafe. Wall-clock timestamps locate events in time; elapsed clocks measure duration.
