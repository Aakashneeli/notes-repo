Week 10 / Lesson 08

Instrument a seam without leaking content

Implement request-correlated AI logs and test both outcomes.

Instrumentation is code that records useful facts about work without changing its result. We will put it around a dependency-injected operation. The fixture makes the seam understandable; your eventual API must place the same responsibility at a real request boundary.

Learn the wrapper mechanism first

def inspect_length(read_text):
    text = read_text()
    print({"event": "text.read", "characters": len(text)})
    return text

The caller supplies a function, not its already-computed result. The wrapper calls it exactly once, observes a safe summary, and returns the original text. It does not print the text. If the read fails, this tiny example emits nothing: that is the failure you must address in the project. An async wrapper uses await operation(). A try/except Exception/else can separate failure and success, with bare raise preserving the original error. Do not catch cancellation as if it were a normal application failure.

Trace inspect_length(lambda: "rain"): lambda creates a small anonymous function; the colon separates its empty parameter list from the expression it returns. Calling read_text() gives "rain"; len(text) is 4; the printed dictionary is {'event': 'text.read', 'characters': 4}; the returned value remains "rain". Passing "rain" directly instead would fail because a string is not callable. Predict the printed length for "rain coat" before checking: it is 9, including the space.

Before the project, try this mechanism in an interactive session: from the weekly root run python, enter the four-line function above, then the two calls with lambda. The ... prompt means Python is waiting for the indented body; enter a blank line to finish the definition. Use exit() to return to the shell. Record your predicted/actual output in the weekly log. Variation: return an empty string; the summary should be 0 while the original empty string is preserved. This tiny exercise prepares the callback mechanism without supplying the assessed async wrapper.

Read the scaffolding before implementing

From the weekly root, read instrumentation.py and the function contract. build_event constructs an allowlisted dictionary; observe times a call and sends that dictionary to emit. An allowlist includes known-safe fields instead of copying arbitrary provider responses and hoping to remove every secret. emit is an injected synchronous function; tests use events.append, while run_observed.py JSON-encodes each event to stdout. The runner creates UUID request IDs and invokes one success and one synthetic timeout. It catches only the deliberate timeout, so an unfinished starter remains visible.

Read test_contract.py. The import path points to this project's folder because the filename has no installed package. unittest runs assertions; IsolatedAsyncioTestCase supplies an event loop for awaited tests. assertIs checks the exact object, not just equal text. The simultaneous-call test catches unsafe global request-ID storage. Leave supplied infrastructure unchanged; add separate tests for any design you extend.

Token and cost arithmetic

Use fictional rates of $2 per million input tokens and $6 per million output tokens. For 100 input and 20 output tokens: (100×2 + 20×6)/1,000,000 = $0.00032. A token is a model-dependent text unit, not necessarily a word. These sample counts are fixture values; rates are not provider pricing. Actual billing can include caching, discounts, reasoning tokens or retries. Label estimates, version rates, and use provider usage fields when available.

Unknown or incomplete counts yield unknown cost. Known counts of zero yield zero. That distinction lets an operator see missing telemetry instead of celebrating an imaginary cost saving.

Project hint — decide the error metadata

The wrapper may know no usage at the instant of failure. Passing None says “unknown”; setting zero says “measured zero.” Do not retry inside an observability wrapper.
