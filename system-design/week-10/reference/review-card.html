A request under stress

Explain without notes

  1. Unavailable vector store: deadline, bounded safe retry, controlled failure, correlated signal, recovery check.
  2. Retry: transient and repeatable? Budget remains? One layer owns retries? Side effect uncertain?
  3. Trust: caller → identity → storage scope → retrieved text → provider → validated output → authorized tools → telemetry.
  4. Latency: time window/volume/errors/tail → one request ID → child timings/queue wait → hypothesis → bounded experiment.

Five views

Context: people/external systems. Containers: running parts. Sequence: order and failure branches. Data flow: information and trust. Deployment: processes, networks and persistence.

Useful checks

Known cost = (input tokens × input USD/million + output tokens × output USD/million) / 1,000,000. Unknown usage stays unknown. Log allowlisted metadata; never dump prompts or exceptions blindly.

Cache keys reflect tenant/permission scope and changing versions. Quota counter and expiry need atomic handling. Repeated jobs need durable keys and a replay policy. Indexes, batching and async work are hypotheses until measured.

Evidence

A diagram is not a deployment. A fixture is not real retrieval. An author check is not a learner assessment. Preserve the attempt, failure, repair and independent variation.
